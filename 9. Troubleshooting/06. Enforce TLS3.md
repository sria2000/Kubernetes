# Nginx & ConfigMap — Enforcing TLS 1.3 Only

## 1. Set Up the Exercise

```bash
wget https://raw.githubusercontent.com/zealvora/certified-kubernetes-administrator/refs/heads/master/Exercises/script-cm-deploy.sh
chmod +x script-cm-deploy.sh
./script-cm-deploy.sh
```

Check the resulting pods:

```bash
k get pods
```

```
NAME                         READY   STATUS    RESTARTS   AGE
myapp-6849dcb48b-zbggw       1/1     Running   0          14m
pod-1                        1/1     Running   0          32m
pod-2                        1/1     Running   0          32m
secure-web-cf8f8988f-fj5sm   1/1     Running   0          44s
```

## 2. Requirement

Modify the setup so the Nginx server in the `secure-web` deployment **only accepts TLS 1.3 connections**. This means editing the ConfigMap associated with the deployment (nginx config) to restrict `ssl_protocols` to `TLSv1.3` only.

### Test Command (used before and after the fix)

**Terminal Tab 1** — forward the service locally:

```bash
kubectl port-forward service/secure-web-svc 8443:443
```

**Terminal Tab 2** — test both TLS versions:

```bash
openssl s_client -connect secure-web.local:8443 -tls1_2
openssl s_client -connect secure-web.local:8443 -tls1_3
```

Before the fix, both commands succeed. After the fix, only `-tls1_3` should succeed.

## 3. Investigate the Current Setup

```bash
k get deployments
k describe deployment secure-web
k get configmap
k get configmap nginx-config-v1 -o yaml
```

## 4. Solution

### Export the Existing ConfigMap and Delete It

ConfigMaps are immutable in the fields that matter here, so the simplest path is export → edit → recreate under a new name.

```bash
k get configmap nginx-config-v1 -o yaml > configmap.yaml
k delete configmap nginx-config-v1
```

### Edit the ConfigMap YAML

```bash
vi configmap.yaml
```

Two changes:
1. Remove `TLSv1.2` from `ssl_protocols`, leaving only:
   ```
   ssl_protocols TLSv1.3;
   ```
2. Rename the ConfigMap to avoid collisions:
   ```
   name: nginx-config-v2
   ```

### Recreate the ConfigMap

```bash
k create -f configmap.yaml
k get configmap
```

```
NAME               DATA   AGE
kube-root-ca.crt   1      11d
nginx-config-v2    1      4s
```

### Update the Deployment to Reference the New ConfigMap

```bash
k edit deployment secure-web
```

Update the volume reference:

```yaml
volumes:
- configMap:
    defaultMode: 420
    name: nginx-config-v2
```

Confirm the pod rolled out with the new config:

```bash
k get pods
```

```
NAME                         READY   STATUS    RESTARTS   AGE
myapp-6849dcb48b-zbggw       1/1     Running   0          22m
pod-1                        1/1     Running   0          40m
pod-2                        1/1     Running   0          40m
secure-web-7c8cbcb86-wk7bb   1/1     Running   0          26s
```

## 6. Clean Up Resources

```bash
kubectl delete deployment secure-web
kubectl delete service secure-web-svc
kubectl delete secret tls-secret
kubectl delete configmap nginx-config-v2
rm configmap.yaml script-cm-deploy.sh
```

## Key Takeaway

Nginx TLS version restriction is controlled by the `ssl_protocols` directive in the config, which in this setup is mounted into the pod via a ConfigMap volume. Since you can't edit a ConfigMap's data and have it retroactively change an immutable field, the safe pattern is: **export → edit → create under a new name → update the deployment's volume reference → verify the rollout** — rather than editing in place.
