# Taint-Based Evictions

## Overview

When a node develops a problem (unreachable, out of resources, etc.), Kubernetes automatically **taints** the node to reflect its condition. Pods running on a tainted node are handled according to their **tolerations** — specifically, `NoExecute` tolerations control whether and how long a Pod is allowed to keep running on a node that has become tainted.

Two possible eviction behaviors:
1. **Immediate eviction** — Pod is evicted as soon as the taint is applied (no toleration, or a toleration with no `tolerationSeconds`)
2. **Brief tolerated downtime** — Pod is allowed to keep running for a grace period before eviction (`tolerationSeconds`), **default is 300 seconds (5 minutes)**

---

## Understanding Taints

Worker nodes are automatically tainted by Kubernetes based on specific node conditions:

- `node.kubernetes.io/not-ready`
- `node.kubernetes.io/unreachable`
- `node.kubernetes.io/out-of-disk`
- `node.kubernetes.io/memory-pressure`
- `node.kubernetes.io/disk-pressure`
- `node.kubernetes.io/network-unavailable`
- `node.kubernetes.io/unschedulable`

These are applied by the **node controller** (part of `kube-controller-manager`) when it detects the corresponding condition, without any manual intervention.

## Demonstration: Watching an Eviction Happen

### 1. Check nodes

```bash
k get nodes
```

```
node01
node02
```

### 2. Deploy a test Pod

```bash
k run nginx --image=nginx
```

Pod is scheduled and running — in this example, on `node02`.

### 3. Simulate a node failure

On `node02`:

```bash
systemctl stop kubelet
# or simulate a hard failure with an actual server halt
```

### 4. Observe from the control plane

```bash
k get nodes
```

`node02` transitions to:

```
NotReady
```

```bash
k get pods -o wide
```

The `nginx` Pod still shows as scheduled on `node02` — it hasn't moved yet.

### 5. Check the taint applied to the node

```bash
k describe node node02
```

Look for the `Taints:` section — the node controller will have applied `node.kubernetes.io/not-ready:NoExecute` automatically.

### 6. Check the Pod's toleration

```bash
k describe pod nginx
```

Look for the `Tolerations:` section. By default, Kubernetes injects a toleration like:

```
node.kubernetes.io/not-ready:NoExecute for 300s
node.kubernetes.io/unreachable:NoExecute for 300s
```

This means the Pod is allowed to keep running on the tainted node for **300 seconds (5 minutes)** before being evicted — giving the node a chance to recover (e.g., kubelet restarts, network blip resolves) without unnecessarily rescheduling the workload.

### 7. After the grace period

Once `tolerationSeconds` (300s) elapses without the node recovering, the Pod is **evicted** from `node02` and **rescheduled onto `node01`**.

## Key Concepts

| Concept | Description |
|---|---|
| **Taint** | Applied to a *node*; signals a condition that Pods should avoid unless they explicitly tolerate it |
| **Toleration** | Applied to a *Pod*; allows the Pod to remain scheduled on (or continue running on) a node with a matching taint |
| **`NoExecute` effect** | Existing Pods without a matching toleration are evicted immediately; Pods with a toleration but no `tolerationSeconds` run indefinitely; Pods with `tolerationSeconds` are evicted once that time elapses |
| **`tolerationSeconds`** | Grace period a Pod is allowed to continue running on a tainted node before eviction — default **300s** for the built-in `not-ready` / `unreachable` tolerations |

## Why This Matters

- Prevents unnecessary Pod churn from transient node blips (e.g., a brief network hiccup or kubelet restart) by giving the node a short window to self-recover.
- If the node doesn't recover within the grace period, workloads are automatically rescheduled elsewhere — this is what keeps a stateless workload available even when a node genuinely fails.
- Directly relevant to homelab troubleshooting: this is the mechanism that explains why Pods on a node that loses its static IP (via DHCP reassignment) don't get rescheduled *immediately* — there's a ~5 minute tolerance window before Kubernetes reacts.
