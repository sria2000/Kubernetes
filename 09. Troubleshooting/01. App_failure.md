# Troubleshoot Application Failure: NodePort Service Not Reachable

## Scenario

A `NodePort` Service was created to expose an `nginx` deployment, but the application is unreachable from outside the cluster.

## Initial Manifest (Broken)

```yaml
apiVersion: v1
kind: Service
metadata:
   name: kplabs-service
spec:
   selector:
     run: nginx
   type: NodePort
   ports:
   - port: 8089
     targetPort: 80
---
apiVersion: v1
kind: Namespace
metadata:
  name: teama
---
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod-first
  labels:
      env: prod
  namespace: teama
spec:
  containers:
  - name: first-pod
    image: nginx
    ports:
        - containerPort: 80
---
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod-second
  labels:
      env: pord
  namespace: teama
spec:
  containers:
  - name: second-pod
    image: nginx
    ports:
        - containerPort: 80
```

## Step 1: Apply the manifest

```bash
root@controlplane:~$ k apply -f node.yaml
service/kplabs-service created
namespace/teama created
pod/nginx-pod-first created
pod/nginx-pod-second created
```

## Step 2: Check the Service


Connection fails. Time to dig into why.

---

## Diagnosis

### Describe the Service

```bash
root@controlplane:~$ k describe service kplabs-service
Name:                     kplabs-service
Namespace:                default
Labels:                   <none>
Annotations:              <none>
Selector:                 run=nginx
Type:                     NodePort
IP Family Policy:         SingleStack
IP Families:              IPv4
IP:                       10.98.130.42
IPs:                      10.98.130.42
Port:                     <unset>  8089/TCP
TargetPort:               80/TCP
NodePort:                 <unset>  30533/TCP
Endpoints:
Session Affinity:         None
External Traffic Policy:  Cluster
Internal Traffic Policy:  Cluster
Events:                   <none>
```

**Key finding: `Endpoints:` is empty.**

A Service with no endpoints means it has no backing Pods to route traffic to — the Service itself is up, but it isn't wired to anything.

### Check the Pods

```bash
root@controlplane:~$ k get pods -n teama
NAME               READY   STATUS    RESTARTS   AGE
nginx-pod-first    1/1     Running   0          4m21s
nginx-pod-second   1/1     Running   0          4m21s
```

Pods are `Running` and healthy — so the problem isn't the Pods themselves, it's the Service not selecting them.

### Root cause

```bash
k describe pods nginx-pod-first   # check the labels
```

Two separate issues surface:

1. **Namespace mismatch** — the Service (`kplabs-service`) was created in the `default` namespace, but the Pods (`nginx-pod-first`, `nginx-pod-second`) live in the `teama` namespace. Services only select Pods within their own namespace.
2. **Label mismatch** — the Service's selector is `run: nginx`, but neither Pod has a `run: nginx` label. The Pods are only labeled `env: prod` (and `env: pord`, itself a typo). A Service's `selector` must match Pod labels exactly for endpoints to populate.

---

## Fix

Update the manifest to:
- Place the Service in the `teama` namespace
- Add the `run: nginx` label to both Pods so they match the Service selector

```yaml
apiVersion: v1
kind: Service
metadata:
   name: kplabs-service
   namespace: teama
spec:
   selector:
     run: nginx
   type: NodePort
   ports:
   - port: 8089
     targetPort: 80
---
apiVersion: v1
kind: Namespace
metadata:
  name: teama
---
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod-first
  labels:
      env: prod
      run: nginx
  namespace: teama
spec:
  containers:
  - name: first-pod
    image: nginx
    ports:
        - containerPort: 80
---
apiVersion: v1
kind: Pod
metadata:
  name: nginx-pod-second
  labels:
      env: pord
      run: nginx
  namespace: teama
spec:
  containers:
  - name: second-pod
    image: nginx
    ports:
        - containerPort: 80
```

## Apply the fix

```bash
root@controlplane:~$ k apply -f node.yaml
service/kplabs-service created
namespace/teama unchanged
pod/nginx-pod-first configured
pod/nginx-pod-second configured
```

## Verify

```bash
k describe service kplabs-service -n teama   # Endpoints should now list Pod IPs
k get endpoints kplabs-service -n teama
curl <node-ip>:<node-port>
```

## Key Takeaways

| Symptom | Root Cause | Fix |
|---|---|---|
| `curl` to NodePort times out / connection refused | Service has no `Endpoints` | Check `k describe svc <name>` for empty `Endpoints:` field |
| Service `Endpoints` empty despite Pods `Running` | Service `selector` doesn't match any Pod `labels` | Ensure Pod labels exactly match the Service's selector key/value pairs |
| Service exists but Pods are unreachable across namespaces | Service and Pods are in different namespaces | Services only select Pods in the **same namespace** — namespace must match, or use a fully qualified DNS name for cross-namespace access (not applicable to label selectors) |

### General troubleshooting flow for "Service not reachable"

1. `k get svc` — confirm the Service exists and has the expected type/port/NodePort
2. `k describe svc <name>` — check the `Endpoints:` field; if empty, the selector isn't matching any Pods
3. `k get pods -n <namespace> --show-labels` — compare Pod labels against the Service's `selector`
4. Confirm the Service and target Pods are in the **same namespace**
5. Once `Endpoints` populates with Pod IPs, test connectivity via the NodePort on any cluster node's IP
