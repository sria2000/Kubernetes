# Asymmetric Key Encryption

## Overview

Asymmetric Key Encryption (also called **Public Key Cryptography**) uses a pair of mathematically related keys to encrypt and decrypt data.

- **Public Key** – Can be shared with everyone.
- **Private Key** – Must be kept secret by the owner.

Unlike symmetric encryption, where the same key is used for encryption and decryption, asymmetric encryption uses **two different keys**.

One key encrypts the data while the opposite key decrypts it.

---

## How It Works

```
                 Public Key
                     │
                     ▼
Plain Text ─────────► Encrypt
                         │
                         ▼
                   Encrypted Data
                         │
                         ▼
                     Decrypt
                 Private Key
                         │
                         ▼
                    Plain Text
```

Likewise, data encrypted with the **private key** can be decrypted using the **public key**, which is commonly used for **digital signatures**.

---

# HTTPS

HTTPS is simply **HTTP secured using TLS (Transport Layer Security).**

It is commonly referred to as:

- HTTP over TLS
- HTTP over SSL (older terminology)

TLS provides:

- Encryption
- Authentication
- Data Integrity

---

# Scenario 1 - Man-In-The-Middle (MITM) Attack

Suppose a user sends login credentials to a web server without encryption.

```
Username : SRILABS
Password : EDUREVL
```

Network Flow

```
+--------+          +-----------+          +------------+
|  User  | -------> | Attacker  | -------> | Web Server |
+--------+          +-----------+          +------------+
                       |
                       |
                       +----------------------+
                       | Hacked Credentials   |
                       | user: SRILABS        |
                       | pass: EDUREVL        |
                       +----------------------+
```

Since the traffic is sent in plain text, the attacker can easily capture the username and password.

---

# Scenario 2 - Integrity Attack

The attacker modifies packets while they are travelling across the network.

Original Payment

```
Transfer £100 to Account A
```

Attacker modifies it to

```
Transfer £10,000 to Account B
```

```
User
   │
   ▼
Transfer £100
   │
   ▼
Attacker modifies packet
   │
   ▼
Transfer £10,000
   │
   ▼
Web Server
```

Without encryption and integrity checks, the receiver cannot detect the modification.

---

# Solution

SSL/TLS protects against:

- Eavesdropping
- Man-In-The-Middle attacks
- Packet Tampering
- Credential Theft

TLS provides:

- Encryption
- Authentication
- Integrity

# Kubernetes Client Certificate Authentication Lab

## Prerequisites

Use a Linux machine connected to your Kubernetes cluster.

Install kubectl

```bash
curl -LO "https://dl.k8s.io/release/$(curl -L -s https://dl.k8s.io/release/stable.txt)/bin/linux/amd64/kubectl"

chmod +x kubectl

sudo mv kubectl /usr/local/bin
```

Copy your kubeconfig

```bash
mkdir -p ~/.kube

nano ~/.kube/config
```

Verify connectivity

```bash
kubectl get pods
```

---

# Step 1 - Generate Private Key and CSR

```bash
mkdir /root/certificates

cd /root/certificates

openssl genrsa -out devops.key 2048

openssl req \
-new \
-key devops.key \
-out devops.csr \
-subj "/CN=devops/O=srilabs"
```

Files created

```
devops.key
devops.csr
```

---

# Step 2 - Encode the CSR

```bash
cat devops.csr | base64 | tr -d '\n'
```

Copy the generated Base64 string.

---

# Step 3 - Create the Kubernetes CSR

Create

```bash
vi csr-request.yaml
```

```yaml
apiVersion: certificates.k8s.io/v1
kind: CertificateSigningRequest

metadata:
  name: devops-csr

spec:
  groups:
  - system:authenticated

  request: ADD-YOUR-BASE64-CSR-HERE

  signerName: kubernetes.io/kube-apiserver-client

  usages:
  - digital signature
  - key encipherment
  - client auth
```

---

# Step 4 - Submit the CSR

```bash
kubectl apply -f csr-request.yaml
```

Verify

```bash
kubectl get csr
```

Expected

```
NAME         AGE   SIGNERNAME                            CONDITION
devops-csr   45s   kubernetes.io/kube-apiserver-client   Pending
```

---

# Step 5 - Approve the CSR

```bash
kubectl certificate approve devops-csr
```

Verify

```bash
kubectl get csr
```

Expected

```
Approved,Issued
```

---

# Step 6 - Download the Certificate

```bash
kubectl get csr devops-csr \
-o jsonpath='{.status.certificate}' \
| base64 -d > devops.crt
```

Files now available

```
devops.key
devops.csr
devops.crt
```

---

# Step 7 - Create Kubernetes Credentials

```bash
kubectl config set-credentials devops \
--client-certificate=devops.crt \
--client-key=devops.key
```

---

# Step 8 - Create a New Context

Replace the cluster name with your cluster.

```bash
kubectl config set-context devops-context \
--cluster=<YOUR_CLUSTER_NAME> \
--user=devops
```

---

# Step 9 - Test the Context

```bash
kubectl --context=devops-context get pods
```

You will most likely receive a **Forbidden** error because RBAC permissions have not yet been granted.

---

# Step 10 - Create an RBAC Role

Create

```bash
vi role.yaml
```

```yaml
apiVersion: rbac.authorization.k8s.io/v1

kind: Role

metadata:
  namespace: default
  name: pod-reader

rules:
- apiGroups: [""]
  resources: ["pods"]
  verbs: ["list"]
```

Apply

```bash
kubectl apply -f role.yaml
```

---

# Step 11 - Create a RoleBinding

Create

```bash
vi rolebinding.yaml
```

```yaml
apiVersion: rbac.authorization.k8s.io/v1

kind: RoleBinding

metadata:
  name: read-pods
  namespace: default

subjects:
- kind: User
  name: devops
  apiGroup: rbac.authorization.k8s.io

roleRef:
  kind: Role
  name: pod-reader
  apiGroup: rbac.authorization.k8s.io
```

Apply

```bash
kubectl apply -f rolebinding.yaml
```

---

# Step 12 - Verify Permissions

```bash
kubectl --context=devops-context get pods
```

Since the certificate user **devops** is now bound to the **pod-reader** Role, listing Pods should succeed.

---

# Step 13 - Cleanup

Delete the resources created during this lab.

```bash
kubectl delete -f role.yaml
```

```bash
kubectl delete -f rolebinding.yaml
```
