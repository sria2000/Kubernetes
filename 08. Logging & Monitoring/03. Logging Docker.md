# Docker Logging Drivers

## Overview

Docker containers generate logs through standard Linux I/O streams.

Every process running inside a container uses three standard streams:

- STDIN (Standard Input)
- STDOUT (Standard Output)
- STDERR (Standard Error)

Docker captures the output from these streams and manages them using a **Logging Driver**.

---

# Linux I/O Streams

## STDIN (Standard Input)

STDIN is the input stream used by an application to receive data.

Example:

```bash
cat
```

The application waits for input from STDIN.

Docker example:

```bash
docker run -it ubuntu bash
```

The terminal input is connected to the container's STDIN.

---

## STDOUT (Standard Output)

STDOUT is the normal output stream of an application.

Example:

```bash
echo "Hello Docker"
```

Output:

```text
Hello Docker
```

Docker captures STDOUT and stores it using the configured logging driver.

Example:

```bash
docker logs <container-name>
```

---

## STDERR (Standard Error)

STDERR is used for error messages.

Example:

```bash
ls /invalid-directory
```

Output:

```text
ls: cannot access '/invalid-directory': No such file or directory
```

Docker captures STDERR and displays it through:

```bash
docker logs
```

---

# Docker Logging Flow

```
              Container Application
                       |
             +---------+---------+
             |                   |
          STDOUT              STDERR
             |                   |
             +---------+---------+
                       |
             Docker Logging Driver
                       |
        Log Storage / External System
```

# Docker Logging Drivers

A Docker Logging Driver controls how container logs are stored, processed, and forwarded.

## Supported Logging Drivers

| Logging Driver | Description |
|---|---|
| json-file | Default Docker logging driver |
| local | Optimized local storage |
| syslog | Sends logs to syslog server |
| journald | Sends logs to systemd journal |
| fluentd | Sends logs to Fluentd collector |
| awslogs | Sends logs to AWS CloudWatch |
| splunk | Sends logs to Splunk |
| gelf | Sends logs to Graylog |

# json-file Logging Driver

The default Docker logging driver is:

```text
json-file
```

Log location:

```text
/var/lib/docker/containers/
```

Directory structure:

```
/var/lib/docker/containers/
 |
 +-- container-id
        |
        +-- container-id-json.log
```

The log file contains:

- STDOUT messages
- STDERR messages
- Timestamp information

Example:

```json
{
 "log":"64 bytes from google.com",
 "stream":"stdout",
 "time":"2026-07-31T20:51:45Z"
}
```

---

# Configure Logging Driver Per Container

Example:

```bash
docker run -d \
--name nginx-container \
--log-driver=json-file \
nginx
```

---

# Configure Log Rotation

Without log rotation, container logs can consume all available disk space.

Example:

```bash
docker run -d \
--name nginx-container \
--log-driver=json-file \
--log-opt max-size=10m \
--log-opt max-file=3 \
nginx
```

Explanation:

## max-size

```text
max-size=10m
```

Maximum size of each log file.

---

## max-file

```text
max-file=3
```

Number of rotated log files to retain.

---

# Configure Default Docker Logging Driver

Configuration file:

```text
/etc/docker/daemon.json
```

Example:

```json
{
  "log-driver": "json-file",
  "log-opts": {
    "max-size": "10m",
    "max-file": "3"
  }
}
```

Restart Docker:

```bash
systemctl restart docker
```

# Docker Logging Best Practices

## 1. Write Application Logs to STDOUT and STDERR

Recommended:

```
Application
     |
     +---- STDOUT
     |
     +---- STDERR
```

Avoid storing application logs only inside the container filesystem.

---

## 2. Enable Log Rotation

Example:

```bash
--log-opt max-size=10m
--log-opt max-file=3
```

Prevents disk exhaustion.

---

## 3. Use Centralized Logging

Production environments commonly use:

- Elasticsearch + Logstash + Kibana (ELK)
- Fluentd
- Fluent Bit
- Splunk
- AWS CloudWatch Logs
- Loki + Grafana

| Component | Purpose |
|---|---|
| STDIN | Input stream to container |
