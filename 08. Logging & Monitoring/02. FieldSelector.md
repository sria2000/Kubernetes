# Kubernetes Field Selectors

## Overview

Field Selectors allow you to filter Kubernetes resources based on the value of specific resource fields.

Unlike Labels, which are user-defined key/value pairs, Field Selectors filter resources using Kubernetes object fields.

Examples of fields:

- `metadata.name`
- `metadata.namespace`
- `status.phase`
- `spec.nodeName`
- `involvedObject.name`

Syntax:

```bash
kubectl get <resource> --field-selector <field>=<value>
```

---

## List All Pods From All Namespaces

Command:

```bash
kubectl get pods --all-namespaces
```

Example:

```text
NAMESPACE     NAME             READY   STATUS
default       nginx-pod        1/1     Running
kube-system   coredns          1/1     Running
```

---

## List All Pods From All Namespaces Except Default Namespace

Command:

```bash
kubectl get pods --field-selector metadata.namespace!=default
```

This returns Pods from all namespaces except the `default` namespace.

---

## List All Pods Except a Specific Pod

Command:

```bash
kubectl get pods --field-selector metadata.name!=<ADD-POD-NAME-HERE>
```

Example:

```bash
kubectl get pods --field-selector metadata.name!=nginx-pod
```

This excludes the specified Pod name from the output.

# Get Events with JSON Output

Command:

```bash
kubectl get events -o json
```

This returns Kubernetes Events in JSON format.

Example:

```json
{
  "apiVersion": "v1",
  "items": [
    {
      "reason": "Scheduled",
      "message": "Successfully assigned pod"
    }
  ]
}
```

---

# Get Events Associated With a Specific Pod

Field selectors are useful for filtering Events related to a specific Kubernetes object.

Command:

```bash
kubectl get events --field-selector involvedObject.name=event-pod
```

Example Output:

```text
LAST SEEN   TYPE      REASON
10s         Normal    Scheduled
8s          Normal    Pulling
5s          Normal    Started
```

---

# Default Field Selector Configuration

Command:

```bash
kubectl get pods --field-selector ""
```

An empty field selector means no filtering is applied.

It returns all Pods.

# Common Field Selector Examples

## Get Running Pods

```bash
kubectl get pods --field-selector status.phase=Running
```

---

## Get Pending Pods

```bash
kubectl get pods --field-selector status.phase=Pending
```

---

## Get Failed Pods

```bash
kubectl get pods --field-selector status.phase=Failed
```

---

## Get Pods Running on a Specific Node

Command:

```bash
kubectl get pods --field-selector spec.nodeName=<node-name>
```

Example:

```bash
kubectl get pods --field-selector spec.nodeName=node01
```

---

# Supported Field Selector Operators

| Operator | Description | Example |
|----------|-------------|---------|
| = | Equal | metadata.name=nginx |
| == | Equal | status.phase==Running |
| != | Not Equal | metadata.namespace!=default |

---

# Field Selector vs Label Selector

| Feature | Field Selector | Label Selector |
|---------|---------------|----------------|
| Based on | Kubernetes object fields | User-defined labels |
| Created by | Kubernetes API | User |
| Custom values | No | Yes |
| Example | metadata.name=nginx | app=frontend |
| Main Usage | Filtering resources | Grouping resources |

# Troubleshooting Using Field Selectors

Workflow:

```
Need specific Kubernetes objects
              |
              v
Identify required field
              |
              v
Use --field-selector
              |
              v
Filter required resources
```

Example:

```bash
kubectl get events --field-selector involvedObject.name=my-pod
```

---

# Important Notes

- Field Selectors work only with Kubernetes-supported fields.
- Field Selectors are different from Label Selectors.
- Field Selectors are useful for troubleshooting and filtering resources in large clusters.
- They are commonly used with:
  - Pods
  - Events
  - Nodes
  - Other Kubernetes API objects
