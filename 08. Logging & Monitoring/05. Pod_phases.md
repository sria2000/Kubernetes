# Kubernetes Pod Lifecycle Phases

## Overview

A Pod represents a running process in Kubernetes.

During its lifecycle, a Pod moves through different phases from creation until termination.

The Kubernetes Pod lifecycle phases are:

```
Pending  -->  Running  -->  Succeeded
                    |
                    |
                  Failed

Unknown
```

---

# Pod Lifecycle Phases

## 1. Pending

A Pod enters the **Pending** phase when:

- The Pod has been created successfully.
- Kubernetes has accepted the Pod definition.
- The Pod is waiting to be scheduled.
- Container images may still be downloading.
- Required resources may not be available.

Common reasons:

- Insufficient CPU
- Insufficient Memory
- No suitable node available
- Image pulling delay
- Scheduling constraints

---

# Pending Phase Example

Create a Pod with very high resource requirements.

## Create Pod Manifest

File:

```bash
vi pending-pod.yaml
```

Manifest:

```yaml
apiVersion: v1
kind: Pod

metadata:
  name: app-pod

spec:
  containers:

  - name: myapp-container
    image: nginx

    resources:
      requests:
        memory: "100Gi"
        cpu: "100"
```

---

## Create Pod

```bash
kubectl create -f pending-pod.yaml
```

---

## Check Pod Status

```bash
kubectl get pods
```

Example:

```text
NAME       READY   STATUS
app-pod    0/1     Pending
```

---

## Describe Pod

```bash
kubectl describe pod app-pod
```

Events:

```text
Events:

Type      Reason             Age   From               Message
----      ------             ---   ----               -------
Warning   FailedScheduling   9s    default-scheduler  0/2 nodes are available: 2 Insufficient cpu, 2 Insufficient memory.
```

Explanation:

The scheduler cannot find a node with enough CPU and memory to run the Pod.

The Pod remains in:

```text
Pending
```

---

# 2. Running

A Pod enters the **Running** phase when:

- The Pod is assigned to a node.
- All required containers are created.
- At least one container is running or starting.

Example:

```bash
kubectl get pods
```

Output:

```text
NAME       READY   STATUS
nginx      1/1     Running
```

---

# 3. Succeeded

A Pod enters the **Succeeded** phase when:

- All containers terminate successfully.
- Containers exit with status code `0`.
- The Pod is not restarted.

Common use cases:

- Batch jobs
- Scripts
- One-time tasks

---

# Succeeded Phase Example

Create Pod:

```bash
nano pod-succeeded.yaml
```

Manifest:

```yaml
apiVersion: v1
kind: Pod

metadata:
  name: test-pod

spec:

  restartPolicy: Never

  containers:

  - name: busybox
    image: busybox

    command:
      - echo
      - "Hello, Kubernetes!"
```

---

## Create Pod

```bash
kubectl create -f pod-succeeded.yaml
```

---

## Check Status

```bash
kubectl get pods
```

Example:

```text
NAME        READY   STATUS
test-pod    0/1     Completed
```

The actual Pod phase is:

```text
Succeeded
```

---

# 4. Failed

A Pod enters the **Failed** phase when:

- All containers terminate.
- At least one container exits with a non-zero status.
- Kubernetes cannot recover by restarting containers.

Common reasons:

- Application crash
- Incorrect command
- Runtime error
- Configuration issue

---

# Failed Phase Example

Create a Pod that exits with error code `1`.

Command:

```bash
kubectl run failpod \
--image=busybox \
--restart=Never \
-- /bin/sh -c "exit 1"
```

---

## Check Status

```bash
kubectl get pods
```

Example:

```text
NAME       READY   STATUS
failpod    0/1     Error
```

Describe:

```bash
kubectl describe pod failpod
```

Check logs:

```bash
kubectl logs failpod
```

---

# Additional Failed Testing

## Invalid Image Example

Create Pod with a non-existing image:

```bash
kubectl run nginx-pod --image=nginx:notexistent
```

Check:

```bash
kubectl get pods
```

Possible status:

```text
ImagePullBackOff
```

Describe:

```bash
kubectl describe pod nginx-pod
```

Events show image pull failures.

---

# Running Pod Example

Create a normal Pod:

```bash
kubectl run curl-pod --image=alpine/curl
```

Check:

```bash
kubectl get pods
```

Example:

```text
NAME        READY   STATUS
curl-pod    1/1     Running
```

---

# 5. Unknown

A Pod enters the **Unknown** phase when:

- Kubernetes cannot determine the Pod status.
- Communication between kubelet and Kubernetes control plane is lost.

Common reasons:

- Node failure
- Network connectivity issue
- Kubelet stopped responding

Example:

```text
NAME       READY   STATUS
app-pod    ?/1     Unknown
```

# Pod Lifecycle Flow

```
              Pod Created
                   |
                   v
              Pending
                   |
                   |
        +----------+----------+
        |                     |
        v                     v
    Running              Scheduling Failed
        |
        |
   +----+----+
   |         |
   v         v
Succeeded  Failed


Node Communication Failure
             |
             v
          Unknown
```

---

# Important Notes

- `Pending` means Kubernetes has accepted the Pod but it is not running yet.
- `Running` means the Pod is assigned to a node and containers are running.
- `Succeeded` means containers completed successfully.
- `Failed` means containers terminated unsuccessfully.
- `Unknown` means Kubernetes cannot determine the Pod state.
- Pod phases are different from Pod conditions and container states.
