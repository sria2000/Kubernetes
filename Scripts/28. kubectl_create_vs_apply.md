# kubectl create vs kubectl apply

One of the most common Kubernetes interview questions is the difference between:

- `kubectl create -f`
- `kubectl apply -f`

Although both can create Kubernetes resources, they behave differently when the resource already exists.

---

# Difference Between `create` and `apply`

| `kubectl create -f` | `kubectl apply -f` |
|---------------------|--------------------|
| Creates a resource for the first time. | Creates the resource if it doesn't exist, or updates it if it already exists. |
| Fails if the resource already exists. | Updates the existing resource without failing. |
| Mainly used for one-time creation. | Used for ongoing configuration management. |
| Not suitable for repeated deployments. | Idempotent (safe to run multiple times). |

---

# Example 1 - Using `kubectl create`

## Pod Manifest

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx
spec:
  containers:
  - name: nginx
    image: nginx
```

Create the Pod

```bash
kubectl create -f pod.yaml
```

Output

```text
pod/nginx created
```

Run the same command again

```bash
kubectl create -f pod.yaml
```

Output

```text
Error from server (AlreadyExists): pods "nginx" already exists
```

**Explanation**

`kubectl create` only creates new resources. If the resource already exists, it returns an error.

---

# Example 2 - Using `kubectl apply`

Create the Pod

```bash
kubectl apply -f pod.yaml
```

Output

```text
pod/nginx created
```

Now modify the YAML.

Change

```yaml
image: nginx
```

to

```yaml
image: nginx:1.27
```

Run

```bash
kubectl apply -f pod.yaml
```

Output

```text
pod/nginx configured
```

**Explanation**

`kubectl apply` detects that the Pod already exists and updates the configuration instead of throwing an error.

# Real-World Workflow

Suppose you have the following Deployment.

```yaml
replicas: 3
```

Deploy it.

```bash
kubectl apply -f deployment.yaml
```

Later, you decide to scale it.

```yaml
replicas: 5
```

Run

```bash
kubectl apply -f deployment.yaml
```

Kubernetes automatically updates the Deployment and creates additional Pods.

There is no need to delete and recreate the Deployment.

---

# How `kubectl apply` Works

`kubectl apply` compares the desired state in the YAML file with the current state in the cluster.

```
Desired State (YAML)
          │
          ▼
   kubectl apply
          │
          ▼
Current Cluster State
```

If differences are found, Kubernetes updates only the changed fields.

# When Should You Use Each?

## Use `kubectl create`

Use it when:

- Learning Kubernetes
- Creating a resource for the first time
- Working with imperative commands
- Performing quick lab exercises

Example

```bash
kubectl create -f pod.yaml
```

---

## Use `kubectl apply`

Use it when:

- Managing production environments
- Working with CI/CD pipelines
- Using GitOps workflows
- Maintaining Kubernetes manifests in Git
- Updating existing resources

Example

```bash
kubectl apply -f deployment.yaml
```

---

# Interview Question

### Q: Which command is preferred in production?

**Answer:** `kubectl apply`

**Reason:**

- Idempotent (safe to run multiple times)
- Updates existing resources
- Works well with version-controlled YAML files
- Standard approach for CI/CD and GitOps

# Quick Comparison

| Feature | `kubectl create -f` | `kubectl apply -f` |
|----------|---------------------|--------------------|
| Creates a new resource | ✅ | ✅ |
| Updates an existing resource | ❌ | ✅ |
| Fails if resource already exists | ✅ | ❌ |
| Safe to run multiple times | ❌ | ✅ |
| Best for Production | ❌ | ✅ |
| Common in CI/CD | ❌ | ✅ |

---

# Summary

- **`kubectl create`** creates a resource only once and fails if it already exists.
- **`kubectl apply`** creates the resource if it doesn't exist and updates it if it does.
- `kubectl apply` is the recommended command for production environments because it supports declarative configuration management and can be safely executed multiple times.

> **Easy way to remember:**
>
> - **`kubectl create` = Create once**
> - **`kubectl apply` = Create or Update (Recommended for real-world use)**
