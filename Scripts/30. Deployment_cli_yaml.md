# Kubernetes Deployment Using Dry Run

## Objective

Learn how to:

- Generate a Deployment YAML without creating the resource
- Save the YAML to a file
- Create a Deployment from the YAML file
- Create a Deployment directly from the command line
- Verify the Deployment and Pods

---

# What is `--dry-run=client`?

The `--dry-run=client` option tells `kubectl` to:

- Validate the command locally.
- Generate the Kubernetes manifest.
- **Do not create** the resource in the cluster.

It is commonly used to generate YAML files before applying them.

---

# Step 1 - Generate Deployment YAML

Generate a Deployment manifest without creating it.

```bash
kubectl create deployment srideploy \
--image=nginx \
--dry-run=client \
-o yaml
```

Output

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  labels:
    app: srideploy
  name: srideploy
spec:
  replicas: 1
  selector:
    matchLabels:
      app: srideploy
  strategy: {}
  template:
    metadata:
      labels:
        app: srideploy
    spec:
      containers:
      - image: nginx
        name: nginx
        resources: {}
status: {}
```

Notice that no Deployment has been created.

---

# Step 2 - Save the YAML to a File

Instead of displaying the YAML on the screen, redirect it to a file.

```bash
kubectl create deployment srideploy \
--image=nginx \
--dry-run=client \
-o yaml > SRI.yaml
```

This creates a file named:

```text
SRI.yaml
```

---

# Step 3 - Create the Deployment from the YAML File

Apply the manifest.

```bash
kubectl apply -f SRI.yaml
```

Output

```text
deployment.apps/srideploy created
```

The Deployment is now created in the cluster.

---

# Step 4 - Create Another Deployment Directly

You can also create a Deployment without generating a YAML file.

```bash
kubectl create deployment srideploy1 --image=nginx
```

Output

```text
deployment.apps/srideploy1 created
```

This command immediately creates the Deployment.

---

# Step 5 - Verify the Deployments

List the Deployments.

```bash
kubectl get deployment
```

Output

```text
NAME         READY   UP-TO-DATE   AVAILABLE   AGE
srideploy    1/1     1            1           19s
srideploy1   1/1     1            1           4s
```

Explanation

- **READY** – Number of available replicas.
- **UP-TO-DATE** – Pods using the latest Deployment configuration.
- **AVAILABLE** – Pods available to serve traffic.
- **AGE** – Time since the Deployment was created.

---

# Step 6 - Verify the Pods

```bash
kubectl get pods
```

Output

```text
NAME                          READY   STATUS    RESTARTS   AGE
frontend                      1/1     Running   0          8m12s
frontendpod                   1/1     Running   0          8m12s
srideploy-85945c7b88-gf6jc    1/1     Running   0          22s
srideploy1-6479bddf45-pqtv4   1/1     Running   0          8s
```

Notice that each Deployment has created its own Pod.

# Why Use `--dry-run=client`?

Using `--dry-run=client` is useful because you can:

- Generate Kubernetes manifests quickly.
- Review the YAML before deployment.
- Store the manifest in Git.
- Modify the configuration before applying it.
- Follow Infrastructure as Code (IaC) best practices.

---

# Useful Commands

Generate Deployment YAML

```bash
kubectl create deployment srideploy \
--image=nginx \
--dry-run=client \
-o yaml
```

Save YAML to a File

```bash
kubectl create deployment srideploy \
--image=nginx \
--dry-run=client \
-o yaml > SRI.yaml
```

Create Deployment from YAML

```bash
kubectl apply -f SRI.yaml
```

Create Deployment Directly

```bash
kubectl create deployment srideploy1 --image=nginx
```

List Deployments

```bash
kubectl get deployment
```

List ReplicaSets

```bash
kubectl get rs
```

List Pods

```bash
kubectl get pods
```

Describe Deployment

```bash
kubectl describe deployment srideploy
```

Delete the Deployments

```bash
kubectl delete deployment srideploy srideploy1
```

---

# Key Takeaways

- `--dry-run=client` generates a Kubernetes manifest without creating the resource.
- `-o yaml` displays the generated YAML.
- Redirecting the output (`>`) saves the manifest to a file.
- `kubectl apply -f` creates resources from a YAML manifest.
- `kubectl create deployment` creates the Deployment immediately without generating a file.
- A Deployment automatically creates a ReplicaSet, which in turn creates the required Pods.
