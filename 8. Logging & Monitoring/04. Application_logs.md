# Kubernetes Application Logs

## Overview

Kubernetes provides the `kubectl logs` command to view application logs generated by containers running inside Pods.

Containers write logs to:

- STDOUT (Standard Output)
- STDERR (Standard Error)

Kubernetes captures these streams and makes them available using `kubectl logs`.

Application logs help with:

- Troubleshooting application issues
- Debugging container failures
- Checking application startup
- Monitoring application behaviour

# Follow Logs in Real Time

Similar to Linux `tail -f`.

```bash
kubectl logs -f <pod-name>
```

Example:

```bash
kubectl logs -f event-pod
```

Exit:


# Multi-Container Pod Logs

For Pods containing multiple containers, specify the container name.

Example Multi-Container Pod:

```yaml
apiVersion: v1
kind: Pod

metadata:
  name: multi-busybox-pod
  labels:
    app: multi-busybox

spec:
  containers:

    - name: busybox-container-1
      image: busybox
      command:
        - sh
        - -c
        - |
          while true;
          do
            echo "Hello from BusyBox Container 1"
            sleep 10
          done

    - name: busybox-container-2
      image: busybox
      command:
        - sh
        - -c
        - |
          while true;
          do
            echo "Hello from BusyBox Container 2"
            sleep 10
          done
```

---

# Create Multi-Container Pod

```bash
kubectl apply -f multi-busybox-pod.yaml
```

Check Pod:

```bash
kubectl get pods | grep multi
```

Output:

```text
multi-busybox-pod     2/2     Running     0     24s
```

`2/2` indicates that both containers inside the Pod are running.

# Get Container Names

For multi-container Pods, first identify the container names.

Command:

```bash
kubectl describe pod multi-busybox-pod
```

Example:

```text
Containers:
  busybox-container-1
  busybox-container-2
```

# View Previous Container Logs

If a container has crashed and restarted:

```bash
kubectl logs <pod-name> --previous
```

Example:

```bash
kubectl logs nginx-pod --previous
```

This displays logs from the previous container instance.

# Important Notes

- `kubectl logs` reads logs from container STDOUT and STDERR.
- Single container Pod:

```bash
kubectl logs <pod-name>
```

- Multi-container Pod:

```bash
kubectl logs <pod-name> -c <container-name>
```

- Kubernetes does not store application logs permanently by default.
- Container logs are stored on the Kubernetes node.
- Applications should write logs to STDOUT/STDERR.
- Production clusters normally use centralized logging solutions.

Examples:

- Elasticsearch + Logstash + Kibana (ELK)
- Fluent Bit
- Fluentd
- Loki + Grafana
- Cloud logging services
