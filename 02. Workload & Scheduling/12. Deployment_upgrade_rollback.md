# Kubernetes Deployment Upgrade and Rollback

## Documentation Referenced

https://kubernetes.io/docs/concepts/workloads/controllers/deployment/

# Objective

In this lab you will learn how to:

- Create a Deployment
- Upgrade the application using a Rolling Update
- View Deployment revision history
- Roll back to a previous version
- Scale a Deployment

---

# Scenario

Current Version

- **NGINX 1.26.3**

Upgrade To

- **NGINX 1.31.2**

Rollback To

- **NGINX 1.26.3**

---

# Step 1 - Create a Deployment

Create a Deployment with 3 replicas.

```bash
kubectl create deployment nginx-test \
--image=nginx:1.26.3 \
--replicas=3
```

Output

```text
deployment.apps/nginx-test created
```

Verify the Deployment image.

```bash
kubectl describe deployment nginx-test | grep -i Image
```

Output

```text
Image: nginx:1.26.3
```

Verify the Pods.

```bash
kubectl get pods
```

Output

```text
NAME                          READY   STATUS
nginx-test-78f49487c4-chmpr   1/1     Running
nginx-test-78f49487c4-dm87t   1/1     Running
nginx-test-78f49487c4-pcfnt   1/1     Running
```

---

# Step 2 - Check Deployment Revision

Deployments maintain revision history.

```bash
kubectl rollout history deployment nginx-test
```

Output

```text
REVISION  CHANGE-CAUSE
1         <none>
```

Currently only **Revision 1** exists.

---

# Step 3 - Upgrade the Deployment

Upgrade the image from **1.26.3** to **1.31.2**.

```bash
kubectl set image deployment/nginx-test nginx=nginx:1.31.2
```

Output

```text
deployment.apps/nginx-test image updated
```

During the upgrade, check the Pods.

```bash
kubectl get pods
```

Example

```text
NAME                          READY   STATUS
nginx-test-new-pod            0/1     ContainerCreating
nginx-test-old-pod1           1/1     Running
nginx-test-old-pod2           1/1     Running
nginx-test-old-pod3           1/1     Running
```

Notice:

- New Pods are created first.
- Old Pods continue serving traffic.
- Once new Pods become Ready, old Pods are terminated.

This process is called a **Rolling Update**.

# Step 4 - Verify the Upgrade

Check the Deployment.

```bash
kubectl describe deployment nginx-test
```

Important sections

```text
Annotations:
deployment.kubernetes.io/revision: 2

StrategyType: RollingUpdate

RollingUpdateStrategy:
25% max unavailable
25% max surge

OldReplicaSets:
nginx-test-78f49487c4 (0 replicas)

NewReplicaSet:
nginx-test-7846698cbf (3 replicas)
```

Verify the image.

```bash
kubectl describe deployment nginx-test | grep -i Image
```

Output

```text
Image: nginx:1.31.2
```

# Understanding the Rolling Update

Deployment performs the upgrade gradually.

Initial State

```
ReplicaSet (Revision 1)
        │
        ├── Pod
        ├── Pod
        └── Pod
```

During Upgrade

```
Old ReplicaSet        New ReplicaSet

Pod                   Pod (new)
Pod                   Pod (new)
Pod
```

After Upgrade

```
ReplicaSet (Revision 2)
        │
        ├── Pod
        ├── Pod
        └── Pod
```

The Deployment ensures:

- Application remains available.
- Downtime is minimized.
- Failed updates can be rolled back.

# Step 5 - View Revision History

```bash
kubectl rollout history deployment nginx-test
```

Output

```text
REVISION  CHANGE-CAUSE
1         <none>
2         <none>
```

Deployment now has two revisions.

---

# Step 6 - Roll Back the Deployment

Rollback to the previous revision.

```bash
kubectl rollout undo deployment nginx-test
```

Output

```text
deployment.apps/nginx-test rolled back
```

Verify the Deployment.

```bash
kubectl get deployment nginx-test
```

Verify the Pods.

```bash
kubectl get pods
```

Verify the image.

```bash
kubectl describe deployment nginx-test | grep -i Image
```

Output

```text
Image: nginx:1.26.3
```

The Deployment has successfully returned to the previous version.

---

# Rollback Flow

```
Revision 1
NGINX 1.26.3
      │
      ▼

Upgrade

      │
      ▼

Revision 2
NGINX 1.31.2
      │
      ▼

kubectl rollout undo

      │
      ▼

Revision 1
NGINX 1.26.3
```

# Step 7 - Scale the Deployment

Increase the number of replicas.

```bash
kubectl scale deployment nginx-test --replicas=10
```

Output

```text
deployment.apps/nginx-test scaled
```

Verify the ReplicaSets.

```bash
kubectl get rs
```

Example

```text
NAME                    DESIRED   CURRENT   READY
nginx-test-7846698cbf   0         0         0
nginx-test-78f49487c4   10        10        10
```

Verify the Pods.

```bash
kubectl get pods
```

You should now see **10 Pods** running.

# Recording Change Cause

By default, the rollout history does not show why a change was made.

You can annotate the Deployment with a change cause.

Example:

```bash
kubectl annotate deployment nginx-test \
kubernetes.io/change-cause="Upgraded nginx from 1.26.3 to 1.31.2" \
--overwrite
```

Then view the history.

```bash
kubectl rollout history deployment nginx-test
```

Example

```text
REVISION  CHANGE-CAUSE
1         Initial Deployment
2         Upgraded nginx from 1.26.3 to 1.31.2
```

You can also inspect a specific revision.

```bash
kubectl rollout history deployment nginx-test --revision=2
```

# Rollback to a Specific Revision

A Deployment can have multiple revisions.

Example:

```bash
kubectl rollout history deployment nginx-test
```

Output

```text
deployment.apps/nginx-test

REVISION  CHANGE-CAUSE
2         <none>
3         Upgraded to nginx 1.26.3
```

Suppose you want to roll back to **Revision 2** instead of the latest previous revision.

Use:

```bash
kubectl rollout undo deployment nginx-test --to-revision=2
```

Output

```text
deployment.apps/nginx-test rolled back
```

Verify the image.

```bash
kubectl describe deployment nginx-test | grep -i Image
```

Output

```text
Image: nginx:latest
```

> **Note:** Since **Revision 2** was running `nginx:latest`, rolling back to that revision restores the Deployment to `nginx:latest`.
# Key Takeaways

- A **Deployment** manages ReplicaSets and Pods.
- Every Deployment change creates a new **Revision**.
- Image upgrades are performed using **Rolling Updates**.
- Rolling Updates replace Pods gradually with minimal downtime.
- Old ReplicaSets are retained for rollback.
- **kubectl rollout undo** restores the previous working version.
- Deployments can be scaled independently without affecting revision history.
- Deployment is the recommended controller for running stateless applications in Kubernetes.
