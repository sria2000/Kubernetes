# Node Capacity, Allocatable & Allocated Resources

## Key Definitions

| Term | Meaning |
|---|---|
| **Capacity** | The total CPU and memory available on the node (hardware-level). |
| **Allocatable** | Resources available for pods, after subtracting what the system/node components use. |
| **Allocated resources** | How much of the allocatable amount is actually given to pods (via requests/limits). |

## Checking Nodes

```bash
k get node
```
```
NAME           STATUS   ROLES           AGE   VERSION
controlplane   Ready    control-plane   11d   v1.35.1
node01         Ready    <none>          11d   v1.35.1
```

## Inspecting a Node's Resources

```bash
k describe node node01
```

```
Capacity:
  cpu:                1
  ephemeral-storage:  19221248Ki
  hugepages-2Mi:      0
  memory:             1948916Ki
  pods:               110
Allocatable:
  cpu:                1
  ephemeral-storage:  18698430040
  hugepages-2Mi:      0
  memory:             1846516Ki
  pods:               110

allocated resources:
  (Total limits may be over 100 percent, i.e., overcommitted.)
  Resource           Requests    Limits
  --------           --------    ------
  cpu                100m (10%)  1 (100%)
  memory             10Mi (0%)   1Gi (56%)
  ephemeral-storage  0 (0%)      0 (0%)
  hugepages-2Mi      0 (0%)      0 (0%)
Events:              <none>
```

> Note: Total **limits** can exceed 100% of allocatable — this is called **overcommitting**, since not all pods use their full limit at the same time.

## Custom Columns: Requests per Pod

Useful for quickly auditing resource requests across the cluster without a full `describe`:

```bash
kubectl get pods --all-namespaces -o custom-columns="NAMESPACE:.metadata.namespace,POD:.metadata.name,CPU_REQUEST:.spec.containers[0].resources.requests.cpu,MEMORY_REQUEST:.spec.containers[0].resources.requests.memory"
```
```
NAMESPACE            POD                                       CPU_REQUEST   MEMORY_REQUEST
default              test-pod                                  <none>        <none>
kube-system          cilium-7l688                              0             0
kube-system          cilium-envoy-rklqx                        0             0
kube-system          cilium-envoy-tc5rr                        0             0
kube-system          cilium-operator-768c98966f-9n259          0             0
```

> `<none>` means the container has no resource request set for that field — it can consume freely up to node limits (or get evicted first under pressure, since it has no guaranteed floor).
