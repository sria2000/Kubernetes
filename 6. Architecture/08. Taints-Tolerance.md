# Taints & Tolerations

**Reference:** https://kubernetes.io/docs/concepts/scheduling-eviction/taint-and-toleration/

## Concept

- **Taint** — a property added to a node that repels certain pods.
- **Toleration** — a "special pass" applied to a pod that lets it be scheduled onto a node with a matching taint (bypasses the repulsion).

Taints are applied to *nodes* to repel pods, and tolerations are applied to *pods* to let them tolerate a taint. It's the opposite of node affinity — taints push pods away rather than attract them.

## Effects

| Effect | Behavior |
|---|---|
| `NoSchedule` | New pods without a matching toleration won't be scheduled here. Existing pods are untouched. |
| `PreferNoSchedule` | Soft version — scheduler tries to avoid it but will place a pod here if there's no better option. |
| `NoExecute` | Strictest — new pods are blocked and any already-running pods without the toleration get evicted. |

## Finding Taints on a Node

```bash
kubectl get nodes
kubectl describe node <node-name>
```

## Tainting a Node

```bash
kubectl taint node worker-01 key=value:NoSchedule
```

> Format: `key=value:effect`

## Defining Toleration - Structure

| Component | Description | Important Pointers |
|---|---|---|
| `key` | The taint key that the toleration applies to. Used to match a taint on a node. | |
| `operator` | Defines the relationship between the key and the value. | - **Equal**: The toleration matches if the key and value are equal.<br>- **Exists**: The toleration matches if the key exists, regardless of the value. |
| `effect` | Specifies the effect of the taint. | |
| `value` | The value associated with the key that the toleration applies to. | Any string value that matches the value of the taint |

## Worked Example

### 1. Test with a Deployment (before toleration)

```bash
kubectl create deployment test-deploy --image=nginx --replicas=5
kubectl get pods -o wide
```

### 2. Generate a Deployment Manifest to Add Tolerations

```bash
kubectl create deployment test-deploy --image=nginx --replicas=5 --dry-run=client -o yaml > deployment-toleration.yaml
```

### 3. Final Manifest with Toleration Added

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  creationTimestamp: null
  labels:
    app: test-deploy
  name: test-deploy
spec:
  replicas: 5
  selector:
    matchLabels:
      app: test-deploy
  strategy: {}
  template:
    metadata:
      creationTimestamp: null
      labels:
        app: test-deploy
    spec:
      containers:
      - image: nginx
        name: nginx
      tolerations:
      - key: "key"
        operator: "Exists"
        effect: "NoSchedule"
```

```bash
kubectl create -f deployment-toleration.yaml
kubectl get pods -o wide
```

### 4. Taint a Node with `NoExecute`

```bash
kubectl taint node worker-01 key=value:NoExecute
kubectl get pods -o wide
```

Pods without a matching toleration get evicted from the node immediately.

## Removing Taints

Append a `-` to the taint definition to remove it:

```bash
kubectl taint node worker-01 key=value:NoSchedule-
kubectl taint node worker-01 key=value:NoExecute-
```
