# CRI Dockerd

**Container Runtime Interface (CRI)** — a plugin interface / API that allows the kubelet to communicate with various container runtimes.

Docker itself doesn't natively implement the CRI, so **cri-dockerd** acts as a shim/adapter that lets the kubelet talk to Docker Engine as if it were a CRI-compliant runtime.

## Reference

- https://github.com/Mirantis/cri-dockerd

## Step 1 — Install Docker and Related Packages

```bash
sudo apt update
sudo apt install -y docker.io golang-go
sudo systemctl enable --now docker
```

## Step 2 — Download and Install CRI-Dockerd

```bash
wget https://github.com/Mirantis/cri-dockerd/releases/download/v0.3.17/cri-dockerd_0.3.17.3-0.ubuntu-jammy_amd64.deb
dpkg -i cri-dockerd_0.3.17.3-0.ubuntu-jammy_amd64.deb
systemctl status cri-docker
systemctl enable cri-docker
```

## Step 3 — Configure Kernel Parameters

```bash
cat <<EOF | sudo tee /etc/sysctl.d/99-kubernetes-cri.conf
net.bridge.bridge-nf-call-iptables  = 1
net.ipv4.ip_forward                 = 1
net.bridge.bridge-nf-call-ip6tables = 1
EOF

sudo sysctl --system

modprobe overlay
modprobe br_netfilter
```

## Step 4 — Configure Kubernetes Repo and Install Components

```bash
sudo apt-get update
apt-get install -y apt-transport-https ca-certificates curl gpg

curl -fsSL https://pkgs.k8s.io/core:/stable:/v1.32/deb/Release.key | sudo gpg --dearmor -o /etc/apt/keyrings/kubernetes-apt-keyring.gpg

echo 'deb [signed-by=/etc/apt/keyrings/kubernetes-apt-keyring.gpg] https://pkgs.k8s.io/core:/stable:/v1.32/deb/ /' | sudo tee /etc/apt/sources.list.d/kubernetes.list

sudo apt-get update

apt-get install -y kubelet=1.32.0-1.1 kubeadm=1.32.0-1.1 kubectl=1.32.0-1.1 cri-tools=1.32.0-1.1

sudo apt-mark hold kubelet kubeadm kubectl
systemctl enable --now kubelet
```

## Step 5 — Initialize the Cluster with kubeadm

The `--cri-socket` flag tells kubeadm (and the kubelet) to use the cri-dockerd socket instead of the default containerd socket.

```bash
kubeadm init --pod-network-cidr=192.168.0.0/16 --kubernetes-version=1.32.0 --cri-socket=unix:///var/run/cri-dockerd.sock

mkdir -p $HOME/.kube
sudo cp -i /etc/kubernetes/admin.conf $HOME/.kube/config
sudo chown $(id -u):$(id -g) $HOME/.kube/config
```

## Step 6 — Remove Taint from Control Plane Node

Allows pods to be scheduled on the control plane node (useful for single-node test clusters).

```bash
kubectl taint nodes --all node-role.kubernetes.io/control-plane-
```

## Step 7 — Install a Network Addon (Calico)

```bash
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.29.1/manifests/tigera-operator.yaml
kubectl create -f https://raw.githubusercontent.com/projectcalico/calico/v3.29.1/manifests/custom-resources.yaml
```

## Step 8 — Verification

```bash
kubectl get nodes
kubectl run nginx --image=nginx
kubectl get pods
```

## Step 9 — Testing (Confirming the Kubelet Depends on cri-docker)

Stop the cri-docker service and try creating a new pod:

```bash
systemctl stop cri-docker
kubectl run nginx-2 --image=nginx
kubectl get pods
journalctl -u kubelet
```

`nginx-2` should fail to start / stay pending, and `journalctl -u kubelet` will show errors — the kubelet can't communicate with any container runtime because the CRI socket is unavailable. This demonstrates that the kubelet's ability to run containers is entirely dependent on the CRI shim being up.

Restart it and confirm recovery:

```bash
systemctl start cri-docker
kubectl get pods
```

## Summary

| Component | Role |
|---|---|
| **kubelet** | Talks to the container runtime via the CRI socket to create/manage pods |
| **cri-dockerd** | Shim that implements the CRI and translates calls into Docker Engine API calls |
| **Docker Engine** | Actually runs the containers |
| **CRI socket** (`unix:///var/run/cri-dockerd.sock`) | The communication channel between kubelet and cri-dockerd |
