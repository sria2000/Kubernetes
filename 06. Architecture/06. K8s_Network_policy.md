# Kubernetes Network Policy

Reference: https://kubernetes.io/docs/concepts/services-networking/network-policies/

## Overview

- Pods can communicate with each other by default.
- If pod1 is compromised, it can communicate to other pods.
- Network policies are a mechanism for controlling network traffic flow in a Kubernetes cluster.

### Types

- **Ingress** – Inbound rule
- **Egress** – Outbound rule

### You can filter based on

- Pods
- Namespace
- IP Blocks

### Pod Selector

Example: allow pods with label `role=app` to connect to `role=database` — other pods denied.

> Not all Kubernetes network plugins support network policy. The ability to enforce network policy must be implemented by the CNI plugin. Some network plugins like Calico, Cilium, etc. support network policy.

---

## YAML Structure

### Part A – Basic fields

- `apiVersion`
- `kind` – NetworkPolicy
- `metadata` – name
- `namespace`

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: test-network-policy
  namespace: default
```

### Part B – Spec content

```yaml
spec:
  podSelector:              ## POD SELECTOR
    matchLabels:
      role: db               ## Attach network policy to role db. You can also give env: production
  policyTypes:               ## PolicyType. Is it inbound or outbound.
  - Ingress
  - Egress

  ingress:                   ## Ingress - incoming
  - from:
    - ipBlock:
        cidr: 172.17.0.0/16
        except:
        - 172.17.1.0/24
    - namespaceSelector:
        matchLabels:
          project: myproject
    - podSelector:
        matchLabels:
          role: frontend
    ports:
    - protocol: TCP
      port: 6379

  egress:                    ## Egress - outgoing
  - to:
    - ipBlock:
        cidr: 10.0.0.0/24
    ports:
    - protocol: TCP
      port: 5978
```

---

## Role of `from` and `to`

| Keyword | Used In | Purpose | Sources/Destinations |
|---|---|---|---|
| **from** | Ingress rule | Specifies the sources of incoming traffic allowed to the selected pods | Other pods, namespaces, or IP blocks |
| **to** | Egress rule | Specifies the destinations of outgoing traffic allowed from the selected pods | Other pods, namespaces, or IP blocks |

## Example 1 – Block All Ingress and Egress

```bash
root@controlplane:~$ k run test-pod --image=alpine/curl -- sleep 3600
pod/test-pod created
root@controlplane:~$ k get pods
NAME       READY   STATUS    RESTARTS   AGE
test-pod   1/1     Running   0          9s

root@controlplane:~$ k exec -it test-pod -- sh
/ # ping google.com
PING google.com (192.178.183.138): 56 data bytes
64 bytes from 192.178.183.138: seq=0 ttl=103 time=11.101 ms
```

Now apply the policy:

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: default-deny-all
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress
```

```bash
root@controlplane:~$ k apply -f net.yaml
networkpolicy.networking.k8s.io/default-deny-all created
```

Now ping fails — **blocked**:

```bash
/ # ping google.com
ping: bad address 'google.com'
```

After deleting the policy, ping works again:

```bash
root@controlplane:~$ k delete -f net.yaml
networkpolicy.networking.k8s.io "default-deny-all" deleted from default namespace
```

> Note: Namespace not given, so it defaults to the `default` namespace.

## Example 2 – Allow Ingress Traffic, Block All Outgoing

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: allow-ingress
spec:
  podSelector: {}
  policyTypes:
  - Ingress
  - Egress

  ingress:
  - {}
```

```bash
root@controlplane:~$ k apply -f net.yaml
networkpolicy.networking.k8s.io/allow-ingress created
```

Create another pod:

```bash
root@controlplane:~$ k run random-pod --image=alpine/curl -- sleep 3600
pod/random-pod created
root@controlplane:~$ k get pods
NAME         READY   STATUS    RESTARTS   AGE
random-pod   1/1     Running   0          4s
test-pod     1/1     Running   0          15m
```

Ping from `random-pod` to `test-pod` fails (egress is denied):

```bash
root@controlplane:~$ k exec -it random-pod -- sh
/ # ping 192.168.1.120

```

This was in the `default` namespace. To test incoming traffic, create a pod in another namespace — **ping works**:

```bash
root@controlplane:~$ k create ns srins
namespace/srins created
root@controlplane:~$ k run sri-pod -n srins --image=alpine/curl -- sleep 3600
pod/sri-pod created
root@controlplane:~$ k exec -it -n srins sri-pod -- sh
/ # ping 192.168.1.70
```

## Example 3 – Isolate Suspicious Pod

Blocks all ingress and egress access to a pod with label `role=suspicious`.

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: block-pod
spec:
  podSelector:
    matchLabels:
      role: suspicious
  policyTypes:
  - Ingress
  - Egress
```

```bash
root@controlplane:~$ k run suspicious-pod --image=alpine/curl -- sleep 3600
pod/suspicious-pod created
root@controlplane:~$ k label pod suspicious-pod role=suspicious
pod/suspicious-pod labeled

root@controlplane:~$ k exec -it suspicious-pod -- sh
/ # ping google.com
# now ping will fail
```

## Example 4 – Allow Based on Pod Selector

Allow `role=app` to connect to `role=database` and deny others.

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: use-podselector
spec:
  podSelector:
    matchLabels:
      role: database
  policyTypes:
  - Ingress

  ingress:
  - from:
    - podSelector:
        matchLabels:
          role: app
```

```bash
root@controlplane:~$ k create -f net.yaml
networkpolicy.networking.k8s.io/use-podselector created

root@controlplane:~$ k get netpol
NAME              POD-SELECTOR      AGE
allow-ingress     role=suspicious   14m
use-podselector   role=database     27s

root@controlplane:~$ k run app-pod --image=alpine/curl -- sleep 3600
pod/app-pod created
root@controlplane:~$ k run database-pod --image=alpine/curl -- sleep 3600
pod/database-pod created

root@controlplane:~$ k label pod database-pod role=database
pod/database-pod labeled
root@controlplane:~$ k label pod app-pod role=app
pod/app-pod labeled

root@controlplane:~$ k get pods -o wide
NAME             READY   STATUS    RESTARTS   AGE    IP              NODE           NOMINATED NODE   READINESS GATES
app-pod          1/1     Running   0          110s   192.168.0.65    controlplane   <none>           <none>
database-pod     1/1     Running   0          99s    192.168.1.31    node01         <none>           <none>
random-pod       1/1     Running   0          25m    192.168.1.70    node01         <none>           <none>
suspicious-pod   1/1     Running   0          13m    192.168.1.149   node01         <none>           <none>
test-pod         1/1     Running   0          40m    192.168.1.120   node01         <none>           <none>
```

`app-pod` → `database-pod` ping **works**:

```bash
root@controlplane:~$ k exec -it app-pod -- sh
/ # ping 192.168.1.31
PING 192.168.1.31 (192.168.1.31): 56 data bytes
64 bytes from 192.168.1.31: seq=0 ttl=63 time=0.506 ms
--- 192.168.1.31 ping statistics ---
1 packets transmitted, 1 packets received, 0% packet loss
round-trip min/avg/max = 0.506/0.506/0.506 ms
```

From `test-pod`, ping to the database **fails**:

```bash
root@controlplane:~$ k exec -it test-pod -- sh
/ # ping 192.168.1.31
PING 192.168.1.31 (192.168.1.31): 56 data bytes
```

## Example 5 – Namespace Selector

```bash
root@controlplane:~$ k create ns prodution
namespace/prodution created

root@controlplane:~$ k get ns --show-labels
NAME                 STATUS   AGE   LABELS
prodution            Active   35s   kubernetes.io/metadata.name=prodution
srins                Active   26m   kubernetes.io/metadata.name=srins
```

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: use-namespace
  namespace: prodution
spec:
  podSelector: {}

  policyTypes:
  - Ingress

  ingress:
  - from:
    - namespaceSelector:
        matchLabels:
          kubernetes.io/metadata.name: security
```

```bash
root@controlplane:~$ k apply -f net.yaml
networkpolicy.networking.k8s.io/use-namespace created

root@controlplane:~$ k create ns security
namespace/security created
root@controlplane:~$ k run security-pod -n security --image=alpine/curl -- sleep 3600
pod/security-pod created

root@controlplane:~$ k get pods -n security -o wide
```

## Example 6 – IP Block

Allow pods from the `production` namespace to connect only to `8.8.8.8` outbound.

```bash
root@controlplane:~$ k create ns production
namespace/production created
```

```yaml
apiVersion: networking.k8s.io/v1
kind: NetworkPolicy
metadata:
  name: restrictip
  namespace: production
spec:
  podSelector: {}

  policyTypes:
  - Egress

  egress:
  - to:
     - ipBlock:
        cidr: 8.8.8.8/32
```

```bash
root@controlplane:~$ k apply -f net.yaml
networkpolicy.networking.k8s.io/restrictip created

root@controlplane:~$ k get netpol -n production
NAME         POD-SELECTOR   AGE
restrictip   <none>         20s

root@controlplane:~$ k run prod-pod -n production --image=alpine/curl -- sleep 3600
pod/prod-pod created

root@controlplane:~$ k exec -it prod-pod -n production -- sh
/ # ping 8.8.8.8
PING 8.8.8.8 (8.8.8.8): 56 data bytes
64 bytes from 8.8.8.8: seq=0 ttl=113 time=11.264 ms
64 bytes from 8.8.8.8: seq=1 ttl=113 time=10.840 ms
--- 8.8.8.8 ping statistics ---
2 packets transmitted, 2 packets received, 0% packet loss
round-trip min/avg/max = 10.840/11.052/11.264 ms
/ # ping 8.8.8.9
PING 8.8.8.9 (8.8.8.9): 56 data bytes
# (blocked, no reply — only 8.8.8.8/32 is allowed)
```

## Network Policies – `except`, `port`, `protocol`

### `except` example

```yaml
ingress:
- from:
  - ipBlock:
      cidr: 172.17.0.0/16
      except:
      - 172.17.1.0/24
```

### `ports` and `protocol` example

```yaml
ingress:
  ports:
  - protocol: TCP
    port: 6379
egress:
- to:
  - ipBlock:
      cidr: 10.0.0.0/24
  ports:
  - protocol: TCP
    port: 5978
```
