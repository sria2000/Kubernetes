# Kubernetes emptyDir Volume

## Overview

An **emptyDir** is an **ephemeral volume** that is created when a **Pod is assigned to a node**. As the name suggests, the volume is initially empty.

All containers within the same Pod can read and write to the same emptyDir volume, making it ideal for sharing data between containers.

The volume exists for the lifetime of the Pod. When the Pod is removed from the node, all data stored in the emptyDir volume is permanently deleted.

Documentation:

- https://kubernetes.io/docs/concepts/storage/ephemeral-volumes/
- https://kubernetes.io/docs/concepts/storage/volumes/#emptydir

---

# Key Characteristics

- Created when a Pod is scheduled onto a node
- Initially empty
- Shared between all containers in the Pod
- Data survives container crashes
- Deleted when the Pod is deleted
- Can use either disk or RAM for storage
- Ideal for temporary data, caches, scratch space and sharing files

---

# Lifecycle

```
Pod Created
      │
      ▼
emptyDir Created (Empty)
      │
      ▼
Containers Read/Write Data
      │
      ▼
Container Restarts
      │
      ▼
Data Still Exists
      │
      ▼
Pod Deleted
      │
      ▼
emptyDir Deleted Permanently
```

---

# Storage Options

## Default (Disk)

Data is stored on the node's local filesystem.

```yaml
volumes:
- name: shared-storage
  emptyDir: {}
```

---

## Memory (RAM)

For faster performance, emptyDir can use RAM instead of disk.

```yaml
volumes:
- name: cache
  emptyDir:
    medium: Memory
    sizeLimit: 500Mi
```

---

# Common Use Cases

- Temporary storage
- Cache directories
- Scratch space
- Share files between containers
- Intermediate processing
- Log sharing
- Build artifacts

# Example 1 - Sharing Files Between Containers

## Base Manifest

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: multi-container-pod
spec:
  containers:
  - name: busybox-container-1
    image: busybox
    command: ["sleep", "36000"]

  - name: busybox-container-2
    image: busybox
    command: ["sleep", "36000"]
```

---

## Final Manifest with emptyDir

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: multi-container-pod

spec:

  volumes:
  - name: srilabs-emptydir
    emptyDir: {}

  containers:

  - name: busybox-container-1
    image: busybox
    command: ["sleep","36000"]

    volumeMounts:
    - name: srilabs-emptydir
      mountPath: /shared-folder

  - name: busybox-container-2
    image: busybox
    command: ["sleep","36000"]

    volumeMounts:
    - name: srilabs-emptydir
      mountPath: /shared-folder
```

Create the Pod

```bash
kubectl apply -f multi-container.yaml
```

Verify

```bash
kubectl get pods
```

Example Output

```text
NAME                  READY   STATUS    RESTARTS   AGE
multi-container-pod   2/2     Running   0          60s
```

---

# Verification

Open a shell inside Container 1

```bash
kubectl exec -it multi-container-pod -c busybox-container-1 -- sh
```

Navigate to the shared directory

```bash
cd /shared-folder
```

Create a file

```bash
touch container-1-file.txt
```

Open a shell in Container 2

```bash
kubectl exec -it multi-container-pod -c busybox-container-2 -- sh
```

Verify the shared file

```bash
cd /shared-folder

ls -la
```

Output

```text
total 8
drwxrwxrwx    2 root root 4096 Jul 31 16:32 .
drwxr-xr-x    1 root root 4096 Jul 31 16:31 ..
-rw-r--r--    1 root root    0 Jul 31 16:32 container-1-file.txt
```

The file created by **Container 1** is immediately visible to **Container 2**, proving both containers share the same emptyDir volume.

# Cleanup

```bash
kubectl delete -f multi-container.yaml
```

# Example 2 - Using RAM as Storage

Create the manifest

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: test-pd

spec:
  containers:
  - name: test-container
    image: busybox:1.36
    command: ["sh","-c","sleep 3600"]

    volumeMounts:
    - name: cache-volume
      mountPath: /cache

  volumes:
  - name: cache-volume
    emptyDir:
      medium: Memory
      sizeLimit: 500Mi
```

Deploy

```bash
kubectl apply -f check_mem.yaml
```

Verify

```bash
kubectl get pod
```

Output

```text
NAME      READY   STATUS    RESTARTS   AGE
test-pd   1/1     Running   0          4s
```

---

# Create Files

Connect to the container

```bash
kubectl exec -it test-pd -- sh
```

Create a file

```bash
cd /cache

echo "Hello Kubernetes" > file1.txt

ls -l

cat file1.txt
```

Output

```text
total 4
-rw-r--r--    1 root root 17 Jul 31 16:36 file1.txt

Hello Kubernetes
```

---

# Verify Memory-backed Storage

Inside the container

```bash
df -h /cache
```

Expected Output

```text
Filesystem      Size  Used Avail Use% Mounted on
tmpfs           500M     0  500M   0% /cache
```

Since the filesystem is **tmpfs**, the volume is backed by **RAM** instead of disk.

---

# Delete the Pod

```bash
kubectl delete pod test-pd
```

Recreate the Pod

```bash
kubectl apply -f check_mem.yaml
```

Verify

```bash
kubectl exec test-pd -- ls /cache
```

Output

```text
<empty>
```

The file has disappeared because **emptyDir only exists for the lifetime of the Pod**.

# emptyDir vs Persistent Volume

| Feature | emptyDir | Persistent Volume |
|----------|----------|-------------------|
| Storage Lifetime | Pod Lifetime | Independent of Pod |
| Survives Container Restart | ✅ Yes | ✅ Yes |
| Survives Pod Deletion | ❌ No | ✅ Yes |
| Shared Between Containers | ✅ Yes | ✅ Yes |
| Uses Local Node Storage | ✅ Yes | Depends on Storage Backend |
| Supports RAM Storage | ✅ Yes (`medium: Memory`) | ❌ No |
| Best For | Temporary Data, Cache, Shared Files | Databases, Long-term Storage |

---

# Summary

- **emptyDir** is an ephemeral volume created when a Pod starts.
- The volume is initially empty.
- All containers in the same Pod can access the same data.
- Data survives container crashes because the volume belongs to the Pod, not the container.
- When the Pod is deleted, all data in the volume is permanently removed.
- By default, data is stored on the node's local disk.
- Setting `medium: Memory` stores the data in RAM (`tmpfs`) for higher performance.
- Common use cases include caches, temporary files, scratch space, and sharing data between multiple containers in the same Pod.
