# Kubernetes hostPath Volume

## Overview

A **hostPath** volume mounts a file or directory from the **host node's filesystem** into a Pod.

Unlike **emptyDir**, the data resides on the worker node itself rather than inside the Pod.

Documentation:

https://kubernetes.io/docs/concepts/storage/volumes/#hostpath

---

# How hostPath Works

```
                Worker Node
        +--------------------------+
        |                          |
        |   /var/log               |
        |   /etc                   |
        |   /data                  |
        |   /                      |
        |        ▲                 |
        +--------|-----------------+
                 |
          hostPath Mount
                 |
                 ▼
        +----------------------+
        |        Pod           |
        |                      |
        | /worker-node-data    |
        +----------------------+
```

The directory from the host becomes available inside the container.

---

# Key Characteristics

- Mounts a file or directory from the worker node
- Data exists outside the Pod
- Survives Pod deletion
- Can mount files or directories
- Multiple Pods on the same node can access the same location
- Primarily intended for testing and single-node environments

---

# Common Use Cases

- Access host log files
- Read host configuration files
- Node monitoring agents
- Backup utilities
- Storage plugins
- Development environments

---

# Important Considerations

- Tightly couples Pods to a specific node
- Pods may fail if scheduled to another node without the same directory
- Can expose sensitive host files
- Not recommended for general application storage in production
- Persistent Volumes (PV) are preferred for production workloads

# Example - Mount the Root Filesystem

Create the manifest

```yaml
apiVersion: v1
kind: Pod

metadata:
  name: test-pod

spec:

  containers:
  - name: test-container
    image: busybox
    command: ["sleep","3600"]

    volumeMounts:
    - name: host-volume
      mountPath: /worker-node-data

  volumes:
  - name: host-volume
    hostPath:
      path: /
```

Deploy the Pod

```bash
kubectl apply -f hostPath.yaml
```

---

# Verify the Pod

```bash
kubectl get pods
```

Example Output

```text
NAME       READY   STATUS    RESTARTS   AGE
test-pod   1/1     Running   0          15s
```

---

# Verify the Mounted Directory

Connect to the Pod

```bash
kubectl exec -it test-pod -- sh
```

List the container filesystem

```bash
ls -l /
```

You should see the mounted directory

```text
worker-node-data
```

Navigate into the mounted directory

```bash
cd /worker-node-data
```

List the contents

```bash
ls -l /
```

Example Output

```text
bin
boot
dev
etc
home
lib
media
mnt
opt
proc
root
run
srv
sys
tmp
usr
var
```

These are the directories from the **worker node's root filesystem**, not the container's own filesystem.

# Verify the Mount

Inside the container

```bash
mount | grep worker-node-data
```

Example Output

```text
/dev/sda1 on /worker-node-data type ext4 (...)
```

or

```bash
df -h /worker-node-data
```

# hostPath vs emptyDir

| Feature | hostPath | emptyDir |
|----------|----------|----------|
| Storage Location | Worker Node Filesystem | Pod Storage |
| Created When | Pod Starts | Pod Starts |
| Deleted When Pod Deletes | ❌ No | ✅ Yes |
| Survives Container Restart | ✅ Yes | ✅ Yes |
| Survives Pod Deletion | ✅ Yes | ❌ No |
| Shared Between Containers | ✅ Yes | ✅ Yes |
| Tied to Specific Node | ✅ Yes | ✅ Yes |
| Suitable for Production | ⚠️ Limited | Temporary Storage Only |

---

# hostPath Types

Kubernetes can automatically create or validate host paths using the **type** field.

Examples

```yaml
hostPath:
  path: /data
  type: Directory
```

```yaml
hostPath:
  path: /data
  type: DirectoryOrCreate
```

Common Types

| Type | Description |
|------|-------------|
| Directory | Directory must already exist |
| DirectoryOrCreate | Create directory if it does not exist |
| File | File must already exist |
| FileOrCreate | Create file if missing |
| Socket | Unix domain socket |
| CharDevice | Character device |
| BlockDevice | Block device |

---

# Summary

- **hostPath** mounts a file or directory from the **worker node** into a Pod.
- Data is stored on the node, not inside the Pod.
- The mounted data survives Pod deletion.
- Useful for node-level utilities such as logging agents and monitoring.
- Because Pods become dependent on a specific node, **hostPath is generally not recommended for production applications**.
- For portable and production-ready storage, use **Persistent Volumes (PV)** and **Persistent Volume Claims (PVC)** instead.
