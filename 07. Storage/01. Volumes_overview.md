# Kubernetes Volumes - Overview

## Overview

Containers in Kubernetes are **ephemeral**, meaning their filesystem is temporary. If a container crashes, restarts, or is recreated, any data stored inside the container is lost.

To solve this problem, Kubernetes provides **Volumes**, which allow containers to store and share data.

Documentation:

https://kubernetes.io/docs/concepts/storage/volumes/

---

# Challenges Without Volumes

## Challenge 1 - State Persistence

Containers do **not** permanently store data.

If a container:

- Crashes
- Restarts
- Is recreated
- Is rescheduled to another node

all files created inside the container are lost.

After a crash, the **kubelet** starts a fresh container with a clean filesystem.

Example

```
Container Starts
        │
        ▼
Create file.txt
        │
        ▼
Container Crashes
        │
        ▼
New Container Starts
        │
        ▼
file.txt ❌ Lost
```

Without persistent storage, application data cannot survive container failures.

---

## Challenge 2 - Sharing Data Between Containers

A Pod can contain multiple containers.

Sometimes these containers need to share files.

Example:

```
+--------------------------------------+
|              Pod                     |
|                                      |
|  +------------+    +--------------+  |
|  | Container1 |    | Container2   |  |
|  | Writes Log |--->| Reads Log    |  |
|  +------------+    +--------------+  |
|             Shared Volume            |
+--------------------------------------+
```

Without a shared volume, containers cannot easily exchange data.

---

# What is a Volume?

A **Volume** is a storage resource attached to a Pod.

It provides a place where data can be stored independently of the container's writable layer.

Benefits:

- Persist application data
- Share files between containers
- Store configuration files
- Store Secrets
- Store application logs
- Mount external storage

---

# Volume Lifecycle

Volumes belong to the **Pod**, not the individual container.

If a container restarts:

- Volume remains available
- Data is preserved

If the Pod is deleted:

- Some volume types are deleted.
- Persistent storage can survive depending on the volume type.

---

# Volume Types

Kubernetes supports many volume types.

Common ones include:

- emptyDir
- ConfigMap
- Secret
- hostPath
- Local
- NFS
- PersistentVolume (PV)
- PersistentVolumeClaim (PVC)
- CSI Volumes

---

# Ephemeral vs Persistent Volumes

## Ephemeral Volumes

Ephemeral volumes exist only for the lifetime of a Pod.

Characteristics

- Created when Pod starts
- Deleted when Pod is deleted
- Temporary storage
- Good for caches and scratch space

Examples

- emptyDir
- ConfigMap
- Secret
- CSI Ephemeral

Example

```
Pod Created
      │
      ▼
Volume Created
      │
      ▼
Pod Deleted
      │
      ▼
Volume Deleted
```

---

## Persistent Volumes

Persistent storage exists independently of Pods.

Characteristics

- Data survives Pod deletion
- Can be reused by new Pods
- Suitable for databases and application data

Examples

- NFS
- Local Persistent Volume
- Cloud Storage
- PersistentVolume (PV)
- PersistentVolumeClaim (PVC)

Example

```
Pod A
   │
   ▼
Persistent Volume
   ▲
   │
Pod B

Same data available
```

# Volume and VolumeMounts

Using a volume requires two steps.

## Step 1 - Define the Volume

Volumes are declared under:

```yaml
spec:
  volumes:
```

Example

```yaml
volumes:
- name: app-storage
  emptyDir: {}
```

---

## Step 2 - Mount the Volume

Mount the volume inside the container.

Volumes are mounted using:

```yaml
spec:
  containers:
    volumeMounts:
```

Example

```yaml
containers:
- name: nginx
  image: nginx

  volumeMounts:
  - name: app-storage
    mountPath: /data
```

---

# Relationship Between Volume and VolumeMount

```
Pod
│
├── volumes
│     │
│     └── app-storage
│
└── Container
      │
      └── volumeMounts
              │
              └── /data
```

The **Volume** defines the storage.

The **VolumeMount** specifies where that storage appears inside the container.

# Common Use Cases

- Store application data
- Database storage
- Share files between containers
- Store logs
- Mount configuration files
- Mount Secrets
- Temporary cache
- Persistent application storage

---

# Summary

| Feature | Description |
|----------|-------------|
| Volume | Storage attached to a Pod |
| VolumeMount | Directory where the volume is mounted inside the container |
| Ephemeral Volume | Exists only while the Pod exists |
| Persistent Volume | Exists independently of Pods |
| Shared Storage | Multiple containers in the same Pod can share data |
| Data Persistence | Allows data to survive container restarts |

---

# Key Takeaways

- Containers are **ephemeral**; their writable filesystem is temporary.
- Volumes solve the problem of data persistence.
- Volumes can also be used to share data between multiple containers in a Pod.
- Define storage using **spec.volumes**.
- Mount storage inside containers using **spec.containers[].volumeMounts**.
- Choose **Ephemeral Volumes** for temporary data and **Persistent Volumes** for long-term storage.
