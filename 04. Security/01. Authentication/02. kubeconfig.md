# KubeConfig File in Kubernetes

## Overview

A **KubeConfig** file is a YAML configuration file used by **kubectl** to connect and authenticate with one or more Kubernetes clusters.

It stores information about:

- Clusters
- Users
- Contexts
- Namespaces
- Authentication Mechanisms

Default location:

```bash
~/.kube/config
```

Use a custom KubeConfig file:

```bash
kubectl get pods --kubeconfig=custom-kubeconfig
```

---

# Viewing the Current KubeConfig

```bash
kubectl config view
```

Example Output

```yaml

    certificate-authority-data: DATA+OMITTED

- context:
    cluster: kubernetes

- name: kubernetes-admin
  user:
    client-certificate-data: DATA+OMITTED
    client-key-data: DATA+OMITTED
```

# Components of a KubeConfig File

## 1. Clusters

Contains the Kubernetes API Server details.

Includes:

- API Server URL
- Certificate Authority (CA)

Example

```yaml
clusters:
- cluster:
    server: https://172.30.1.2:6443
    certificate-authority-data: DATA+OMITTED
  name: kubernetes
```

---

## 2. Users

Contains authentication information.

Authentication methods include:

- Client Certificates
- Bearer Tokens
- Username/Password
- External Authentication Plugins

Example

```yaml
users:
- name: kubernetes-admin
  user:
    client-certificate-data: DATA+OMITTED
    client-key-data: DATA+OMITTED
```

---

## 3. Contexts

A Context links together:

- Cluster
- User
- Default Namespace (Optional)

Think of a Context as:

```
User + Cluster + Namespace
```

Example

```yaml
contexts:
- context:
    cluster: kubernetes
    user: kubernetes-admin
  name: kubernetes-admin@kubernetes
```

---

# KubeConfig Structure

```
                KubeConfig
                     │
     ┌───────────────┼───────────────┐
     │               │               │
 Clusters         Users          Contexts
     │               │               │
 API Server      Authentication   User + Cluster
 CA Cert         Certificates     Namespace
```

# Creating a KubeConfig from Scratch

## Step 1 - Add Development Cluster

```bash
kubectl config \
--kubeconfig=base-config \
set-cluster development \
--server=https://1.2.3.4
```

---

## Step 2 - Add Development User

```bash
kubectl config \
--kubeconfig=base-config \
set-credentials development-admin \
--username=test-user \
--password=some-password
```

---

## Step 3 - Create Development Context

```bash
kubectl config \
--kubeconfig=base-config \
set-context dev-cluster \
--cluster=development \
--namespace=dev \
--user=development-admin
```

---

## Step 4 - Add Production Cluster

```bash
kubectl config \
--kubeconfig=base-config \
set-cluster production \
--server=https://4.5.6.7
```

---

## Step 5 - Add Production User

```bash
kubectl config \
--kubeconfig=base-config \
set-credentials production-admin \
--username=prod-user \
--password=prod-password
```

---

## Step 6 - Create Production Context

```bash
kubectl config \
--kubeconfig=base-config \
set-context prod-cluster \
--cluster=production \
--namespace=prod \
--user=production-admin
```

# Common KubeConfig Commands

View the KubeConfig

```bash
kubectl config view
```

View Contexts

```bash
kubectl config get-contexts
```

View Current Context

```bash
kubectl config current-context
```

View Clusters

```bash
kubectl config get-clusters
```

View Users

```bash
kubectl config get-users
```

Switch Context

```bash
kubectl config use-context <context-name>
```

Delete Context

```bash
kubectl config delete-context <context-name>
```

Delete User

```bash
kubectl config unset users.<user-name>
```

Delete Cluster

```bash
kubectl config unset clusters.<cluster-name>
```

---

# Summary

| Component | Purpose |
|------------|---------|
| Cluster | Stores API Server URL and CA Certificate |
| User | Stores authentication information (certificates, token, username/password) |
| Context | Links a User to a Cluster and optionally sets a default Namespace |
| Current Context | The active Cluster/User combination used by kubectl |
| Default Location | `~/.kube/config` |
| Custom KubeConfig | `kubectl --kubeconfig=<file>` |

---

# Key Takeaways

- KubeConfig is a YAML configuration file used by **kubectl**.
- It can manage multiple Kubernetes clusters.
- A **Context** links together a **Cluster**, **User**, and optional **Namespace**.
- Use `kubectl config use-context` to switch between clusters.
- Use `--kubeconfig=<file>` to work with custom configuration files.
- The default KubeConfig file is stored in `~/.kube/config`.
