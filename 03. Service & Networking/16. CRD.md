# Custom Resource Definitions (CRD)

Documentation Referenced:

https://kubernetes.io/docs/tasks/extend-kubernetes/custom-resources/custom-resource-definitions/

---

Kubernetes provides a set of default resources that are available out of the box.

You can view the available resources using:

```bash
kubectl api-resources
```

Examples of default Kubernetes resources:

- Pod
- Service
- Deployment
- ReplicaSet
- StatefulSet
- ConfigMap
- Secret
- Job
- CronJob

Sometimes applications require resources that are not available by default in Kubernetes.

Examples:

- Database
- Backup
- Certificate
- Application
- Virtual Machine

To create our own Kubernetes resource types, we use **Custom Resource Definitions (CRD)**.

---

# What is a Custom Resource Definition (CRD)

A Custom Resource Definition allows you to extend the Kubernetes API by defining your own custom resource types.

A CRD:

- Extends the Kubernetes API
- Defines a new object kind
- Allows users to create custom resources
- Makes the Kubernetes API server serve the new resource type

After creating a CRD:

1. Kubernetes API server registers the new resource
2. The new resource becomes available through kubectl
3. Users can create custom objects using that resource

# Create a Custom Resource Definition

Create a CRD YAML file:

```bash
vi crd.yaml
```

Example:

```yaml
apiVersion: apiextensions.k8s.io/v1
kind: CustomResourceDefinition

metadata:
  name: databases.srilabs.internal

spec:
  group: srilabs.internal

  names:
    kind: Database
    listKind: DatabaseList
    plural: databases
    singular: database

  scope: Namespaced

  versions:
    - name: v1
      served: true
      storage: true

      schema:
        openAPIV3Schema:
          type: object

          properties:
            spec:
              type: object

              properties:
                name:
                  type: string

                replicas:
                  type: integer
```

---

# Apply CRD

Create the CRD in Kubernetes:

```bash
kubectl apply -f crd.yaml
```

Output:

```bash
customresourcedefinition.apiextensions.k8s.io/databases.srilabs.internal created
```

# Create Custom Resource Object

Once the CRD exists, Kubernetes understands the new resource type.

Create:

```bash
vi db.yaml
```

Example:

```yaml
apiVersion: srilabs.internal/v1

kind: Database

metadata:
  name: my-database

spec:
  name: test-db
  replicas: 3
```

---

# Create Custom Resource

Command:

```bash
kubectl create -f db.yaml
```

Output:

```bash
database.srilabs.internal/my-database created
```

Command:


---

# Delete CRD

Command:

```bash
kubectl delete -f crd.yaml
```

Important:

Deleting a CRD also deletes all custom resources created from that CRD.

# CRDs with Helm 3

Helm 3 introduced a special directory called:

```
crds/
```

inside a Helm chart.

Example:

```
my-chart
|
|-- Chart.yaml
|
|-- values.yaml
|
|-- templates/
|
|-- crds/
      |
      |-- database-crd.yaml
```

Helm installs CRDs from the `crds/` directory before installing templates.

---

# Helm CRD Installation Behaviour

Install Helm chart:

```bash
helm install my-release my-chart
```

Helm installs CRDs first from:

```
crds/
```

If the CRD already exists:

- Helm skips the installation
- Warning message is displayed

---

# Skip CRD Installation

Helm provides:

```bash
--skip-crds
```

Example:

```bash
helm install my-argo-cd argo/argo-cd \
--version 7.8.23 \
--skip-crds \
--dry-run
```

---

# Add Argo Helm Repository

Command:

```bash
helm repo add argo https://argoproj.github.io/argo-helm
```

# Check Standard Helm Approach

Command:

```bash
helm install my-argo-cd argo/argo-cd \
--version 7.8.23 \
--skip-crds \
--dry-run | grep CustomResourceDefinition
```

This skips CRD installation.

---

# Disable CRD Installation Using Helm Values

Some Helm charts provide a value to control CRD installation.

Example:

```bash
helm install my-argo-cd argo/argo-cd \
--version 7.8.23 \
--set crds.install=false \
--dry-run
```

Check:

```bash
helm install my-argo-cd argo/argo-cd \
--version 7.8.23 \
--set crds.install=false \
--dry-run | grep CustomResourceDefinition
```

---

# Render Helm Templates Without CRDs

Command:

```bash
helm template my-argo-cd argo/argo-cd \
--version 7.8.23 \
--set crds.install=false \
> argo-no-crd.yaml
```

This generates Kubernetes manifests without CRD definitions.

---

# Key Points

- CRD extends the Kubernetes API
- CRD creates new Kubernetes resource types
- Custom Resources are objects created from CRDs
- Kubernetes API server automatically exposes CRD resources
- Operators heavily depend on CRDs
- Helm 3 supports CRDs using the `crds/` directory
- Existing CRDs are skipped by Helm
- `--skip-crds` prevents Helm CRD installation
- `crds.install=false` disables CRD installation for supported Helm charts
