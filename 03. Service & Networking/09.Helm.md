# Helm — Package Manager for Kubernetes

## 1. What is Helm?

Kubernetes apps rarely consist of just one object. A single application or service can involve a `Deployment`, `Service`, `Ingress`, `Secret`, `ConfigMap`, `LoadBalancer`, `Volumes`, and more. Managing all of these by hand — especially across environments — gets messy fast.

**Helm** is the package manager for Kubernetes. It combines all of these individual resource definitions into one versioned, reusable package called a **Chart**.

### Key concepts

| Term | Meaning |
|---|---|
| **Chart** | A Helm package. Contains **all** the resource definitions necessary to run an application, tool, or service inside a Kubernetes cluster (e.g. `packages/helm/bitnami/nginx`). |
| **Repo (Repository)** | A place where Charts are collected, hosted, and shared — similar to how `apt`/`yum` repos host OS packages. |
| **Release** | A specific instance of a Chart that has been installed into a cluster. You can install the same Chart multiple times under different release names. |

> 📌 **Tip:** Think of a Chart like a template/blueprint, and a Release like the actual running instance created from that blueprint — the same relationship as a Docker image vs. a running container.

Reference: [helm.sh — Install Helm](https://helm.sh/docs/intro/install/)

## 2. Installing Helm (Ubuntu / Debian)

```bash
curl https://baltocdn.com/helm/signing.asc | gpg --dearmor | sudo tee /usr/share/keyrings/helm.gpg > /dev/null
sudo apt-get install apt-transport-https --yes
echo "deb [arch=$(dpkg --print-architecture) signed-by=/usr/share/keyrings/helm.gpg] https://baltocdn.com/helm/stable/debian/ all main" | sudo tee /etc/apt/sources.list.d/helm-stable-debian.list
sudo apt-get update
sudo apt-get install helm
```

### Verify Helm is working
```bash
helm
```

> 📌 **Tip:** This installs the Helm **client only** — Helm 3 (current) needs no server-side component (`tiller` was removed after Helm 2), so there's nothing extra to deploy into the cluster itself.

## 3. Finding Charts — Artifact Hub

[Artifact Hub](https://artifacthub.io/) is the central, community-run index of Helm Charts across many repositories (Bitnami, Argo, Prometheus, etc.) — the Helm equivalent of Docker Hub.

Example: [artifacthub.io/packages/helm/bitnami/nginx](https://artifacthub.io/packages/helm/bitnami/nginx)

> 📌 **Tip:** Artifact Hub is a *catalog*, not a repo host itself — you still need to `helm repo add` the actual repo URL shown on the package page before you can install from it.

## 4. Installing a Chart — nginx Example

```bash
helm repo add bitnami https://charts.bitnami.com/bitnami
helm install my-nginx bitnami/nginx
```
```bash
kubectl get pods
```
```
NAME                        READY   STATUS    RESTARTS   AGE
my-nginx-57fd75c6f9-fnh9d   0/1     Running   0          11s
```

> 📌 **Tip:** The syntax is `helm install <release-name> <repo>/<chart>`. If you don't pass a release name, Helm generates a random one — always name it explicitly in real environments so `helm list` stays readable.

## 5. Everyday Helm Commands

```bash
helm list                        # List installed releases
helm repo list                   # List added repositories
helm search repo bitnami         # Search within added repos
helm search hub nginx            # Search across Artifact Hub
helm template bitnami/nginx      # Render manifests locally, don't install
helm template bitnami/nginx > nginx.yaml                 # Save rendered manifests to a file
helm template bitnami/nginx -n custom-ns > nginx.yaml     # Render as if targeting a specific namespace
helm uninstall my-nginx          # Remove a release
```

### Example output
```
root@controlplane:~$ helm list
NAME            NAMESPACE       REVISION        UPDATED                                 STATUS          CHART           APP VERSION
my-nginx        default         1               2026-07-30 11:39:07.454271425 +0000 UTC deployed        nginx-25.0.16   1.31.3

root@controlplane:~$ helm repo list
NAME    URL
bitnami https://charts.bitnami.com/bitnami
```

> 📌 **Tip:** `helm template` never talks to the cluster or the Helm release history — it's pure client-side rendering. It's the fastest way to review exactly what YAML a chart + your values would produce before committing to `helm install`.

## 6. Handling CRDs — Argo CD Example

Some charts (like Argo CD) ship **CustomResourceDefinitions (CRDs)**. CRDs are cluster-scoped and can conflict with existing installs, so it's common to inspect or skip them before installing.

```bash
helm repo add argo https://argoproj.github.io/argo-helm
```

### Dry-run and inspect what CRDs would be installed
```bash
helm install my-argo-cd argo/argo-cd --version 7.8.23 --skip-crds --dry-run
helm install my-argo-cd argo/argo-cd --version 7.8.23 --skip-crds --dry-run | grep CustomResourceDefinition
```

### Skipping CRDs via chart values instead of the flag
```bash
helm install my-argo-cd argo/argo-cd --set crds.install=false --dry-run | grep CustomResourceDefinition
```

### Render manifests without CRDs, saved to a file
```bash
helm template my-argo-cd argo/argo-cd --set crds.install=false --version 7.8.23 > argo-no-crd.yaml
```

> 📌 **Tip:** `--skip-crds` (a Helm install-time flag) and `--set crds.install=false` (a chart-specific values override) are **not the same mechanism** — `--skip-crds` is generic to Helm 3 and works on any chart that ships CRDs the standard way, while `crds.install=false` only works if the chart author specifically wired up that values key. Always check the chart's `values.yaml`/README to see which one it actually supports.

> 📌 **Tip:** Always pin `--version` in real environments (`--version 7.8.23`) — without it, Helm installs whatever the latest chart version is at that moment, which can silently pull in breaking changes.

## 7. Additional Tips & Gotchas

- **Helm 2 vs Helm 3:** Helm 2 required a server-side component called `tiller` running in-cluster, which was a long-standing security concern (cluster-wide privileges). Helm 3 removed it entirely — the Helm CLI talks directly to the Kubernetes API using your existing kubeconfig/RBAC.
- **Values files:** Instead of long `--set` chains, use `-f myvalues.yaml` to pass a full values override file — much easier to version-control and diff.
- **Upgrades:** `helm upgrade <release> <chart>` applies new values/chart versions to an existing release; `helm rollback <release> <revision>` reverts to a previous one. `helm history <release>` shows the revision list.
- **Namespaces:** `helm install` doesn't create the namespace for you by default — use `--create-namespace` alongside `-n <namespace>` if it doesn't already exist.
- **Uninstall keeps history by default in some setups:** use `helm uninstall <release> --keep-history` deliberately if you want to `helm rollback` after a full uninstall; otherwise release history is deleted too.
- **Debugging a bad install:** `helm install ... --dry-run --debug` renders the manifests **and** shows the computed values, which is the fastest way to see why a template isn't producing what you expect, before anything touches the cluster.
- **Chart dependencies:** Charts can declare sub-charts in `Chart.yaml` under `dependencies`. Run `helm dependency update` to pull them into the `charts/` folder before installing/packaging.
- **Linting your own charts:** `helm lint <chart-dir>` catches common structural issues before you package or publish a chart you've written yourself.

## Quick Reference — Commands Used

```bash
helm search <repo/hub> <keyword>
helm repo add <name> <url>
helm repo list
helm install <release> <chart> [--version <ver>] [--set key=value] [-f values.yaml] [--dry-run] [--debug]
helm upgrade <release> <chart>
helm rollback <release> <revision>
helm list
helm history <release>
helm uninstall <release>
helm template <release> <chart> [-n <namespace>] [--set key=value] > output.yaml
helm dependency update <chart-dir>
helm lint <chart-dir>
```

## Helm Command Reference (Summary Table)

| Helm Command | Description |
|---|---|
| `helm search <repo/hub> <keyword>` | Search for Helm charts in Artifact Hub and/or repositories you've added |
| `helm repo add <name> <url>` | Adds a Helm chart repository (e.g. bitnami) |
| `helm install <release> <chart>` | Installs a chart as a release into Kubernetes |
| `helm uninstall <release>` | Uninstalls (deletes) a Helm release |
| `helm list` | Lists all installed Helm releases |
| `helm template <release> <chart>` | Renders Kubernetes manifests locally without installing |
