# Kubernetes Named Ports

## Overview

Kubernetes allows us to associate a **name** with a container port.

Instead of specifying the port number while creating a Service, we can specify the **port name**.

Example:

Without Named Port:

```yaml
targetPort: 80
```

With Named Port:

```yaml
targetPort: http
```

where `http` is the name assigned to the container port.

---

# Why Use Named Ports?

Benefits:

- Improves readability
- Avoids hard-coding port numbers
- Makes Service definitions easier to maintain
- Allows applications to change container ports without modifying Service configuration

---

# Named Port Architecture

```
Service
   |
   |
   | targetPort: http
   |
   v
Pod Container Port

   name: http
   containerPort: 80
```

The Service `targetPort` must match the container port `name`.

---

# Named Port Syntax

## Pod Definition

```yaml
apiVersion: v1
kind: Pod

metadata:
  name: nginx

spec:
  containers:
  - name: nginx
    image: nginx

    ports:
    - containerPort: 80
      name: http
```

Here:

```
Port Number : 80
Port Name   : http
```

---

# Service Definition Using Named Port

```yaml
apiVersion: v1
kind: Service

metadata:
  name: nginx-service

spec:

  selector:
    app: nginx

  ports:
  - port: 80
    targetPort: http
```

The Service does not use:

```yaml
targetPort: 80
```

Instead it uses:

```yaml
targetPort: http
```

Kubernetes finds the container port:

```yaml
name: http
```

inside the Pod.

---

# Use Case 1: Create Pod and Service Using Named Port

## Step 1: Generate Pod YAML

Command:

```bash
kubectl run nginx \
--image=nginx \
--port=80 \
--dry-run=client \
-o yaml
```

Example generated YAML:

```yaml
apiVersion: v1
kind: Pod

metadata:
  labels:
    run: nginx
  name: nginx

spec:
  containers:
  - image: nginx
    name: nginx

    ports:
    - containerPort: 80
```

---

## Add Named Port

Modify the Pod YAML:

```yaml
ports:
- containerPort: 80
  name: http
```

Final:

```yaml
apiVersion: v1
kind: Pod

metadata:
  labels:
    run: nginx
  name: nginx

spec:

  containers:
  - image: nginx
    name: nginx

    ports:
    - containerPort: 80
      name: http
```

Apply:

```bash
kubectl apply -f pod_named.yaml
```

---

# Step 2: Create Service Using Named Port

Command:

```bash
kubectl expose pod nginx \
--name first-svc \
--port=80 \
--target-port=http \
--type=NodePort
```

Notice:

```
--target-port=http
```

Instead of:

```
--target-port=80
```

---

# Verify Service

Command:

```bash
kubectl get svc
```

Example output:

```
NAME         TYPE        CLUSTER-IP       PORT(S)

first-svc    NodePort    10.110.144.197   80:30382/TCP

kubernetes   ClusterIP   10.96.0.1        443/TCP
```

---

# Verify Service YAML

Command:

```bash
kubectl get svc first-svc -o yaml
```

Example:

```yaml
spec:

  ports:
  - nodePort: 30382
    port: 80
    protocol: TCP
    targetPort: http

  selector:
    run: nginx

  type: NodePort
```

Important:

```yaml
targetPort: http
```

matches:

```yaml
name: http
```

inside the Pod.

---

# Step 3: Verify Connectivity

Get Node IP:

```bash
kubectl get nodes -o wide
```

Example:

```
NAME           INTERNAL-IP
```

Get NodePort:


# Use Case 2: Add Named Port to Existing Pod

## Create Pod YAML

Command:

```bash
kubectl run nginx \
--image=nginx \
--port=80 \
--dry-run=client \
-o yaml > pod_named.yaml
```

View:

```bash
cat pod_named.yaml
```

Example:

```yaml
apiVersion: v1
kind: Pod

metadata:
  labels:
    run: nginx

  name: nginx

spec:

  containers:
  - image: nginx
    name: nginx

    ports:
    - containerPort: 80
```

---

# Add Custom Named Port

Update:

```yaml
ports:

- containerPort: 80
  name: custom-http
```

Final:

```yaml
apiVersion: v1
kind: Pod

metadata:
  labels:
    run: nginx
  name: nginx

spec:

  containers:
  - image: nginx
    name: nginx

    ports:
    - containerPort: 80
      name: custom-http
```

Apply:

```bash
kubectl apply -f pod_named.yaml
```

---

# Important: Pod Fields Are Immutable

If the Pod already exists and we add:

```yaml
name: custom-http
```

Kubernetes rejects the change.

Example error:

```
The Pod "nginx" is invalid:

spec: Forbidden:
pod updates may not change fields other than

spec.containers[*].image
spec.initContainers[*].image
spec.activeDeadlineSeconds
spec.tolerations
```

Reason:

Most Pod specification fields cannot be modified after creation.

---

# Solution

Delete and recreate the Pod:

```bash
kubectl delete pod nginx
```

Create again:

```bash
kubectl apply -f pod_named.yaml
```

Now the named port will be created successfully.

---

# Interview Notes

- Named ports are defined at container level.
- Services reference named ports using `targetPort`.
- The Service targetPort name must exactly match the container port name.
- Named ports improve readability and maintainability.
- Pod port names cannot be changed after Pod creation.
- For production workloads, update Deployments instead of directly modifying Pods.
