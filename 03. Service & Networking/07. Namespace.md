Documentation Referenced:

---

# What is a Namespace?

A **Namespace (NS)** is a logical partition inside a Kubernetes cluster that provides a mechanism for isolating groups of resources.

Each namespace has its own set of Kubernetes resources such as:

- Pods
- Services
- ConfigMaps
- Secrets
- Deployments
- ReplicaSets
- StatefulSets

Namespaces allow multiple teams or applications to share the same Kubernetes cluster without interfering with one another.

---

# Why do we need Namespaces?

Imagine a company has multiple teams using the same Kubernetes cluster.

Without namespaces:

- Pod names could conflict.
- ConfigMaps and Secrets would be mixed together.
- It would be difficult to manage resources.

Namespaces solve this by providing isolation.

Example:

```
Single Kubernetes Cluster

├── Development Namespace
│     ├── Pods
│     ├── ConfigMaps
│     ├── Secrets
│
├── UAT Namespace
│     ├── Pods
│     ├── ConfigMaps
│     ├── Secrets
│
└── Production Namespace
      ├── Pods
      ├── ConfigMaps
      ├── Secrets
```

---

# Real World Example

Suppose your company has three environments:

- Development
- UAT
- Production

Instead of creating three Kubernetes clusters, you can create three namespaces.

```
Cluster

├── DEV Namespace
├── UAT Namespace
└── PROD Namespace
```

Each namespace contains its own applications and configuration.

This reduces infrastructure costs while maintaining logical separation.

# Default Namespaces in Kubernetes

Kubernetes automatically creates several namespaces.

| Namespace | Description |
|-----------|-------------|
| **default** | Used for resources that do not specify a namespace. |
| **kube-system** | Contains Kubernetes system components such as CoreDNS, API Server, Scheduler, etc. |
| **kube-public** | A namespace readable by all users, often used for publicly accessible cluster information. |
| **kube-node-lease** | Stores node heartbeat lease objects used for node health monitoring. |

Depending on the Kubernetes distribution, you may also see additional namespaces such as:

- local-path-storage
- cilium-secrets
- ingress-nginx

# Create a Namespace

Create a Development namespace.

```bash
kubectl create namespace development
```

```text

```

Create a UAT namespace.

```bash
kubectl create namespace uat
```

Output

```text
namespace/uat created
```

# Generate YAML with Namespace

Use dry-run to generate YAML.

```bash
kubectl run uat-pod \
--image=nginx \
-n uat \
--dry-run=client \
-o yaml
```

Output

```yaml
apiVersion: v1
kind: Pod

metadata:
  labels:
    run: uat-pod
  name: uat-pod
  namespace: uat

spec:
  containers:
  - image: nginx
    name: uat-pod

  dnsPolicy: ClusterFirst
  restartPolicy: Always
```

Notice the generated YAML includes:

```yaml
metadata:
  namespace: uat
```

This ensures the Pod is created inside the **uat** namespace.

# Namespace Isolation

Namespaces isolate resources.

Example:

```
Development Namespace

Pod:
nginx

ConfigMap:
db-config

Secret:
db-password
```

```
UAT Namespace

Pod:
nginx

ConfigMap:
db-config

Secret:
db-password
```

Although the resource names are identical, they do not conflict because they belong to different namespaces.

# Common Namespace Commands

List namespaces

```bash
kubectl get namespaces
```

Create namespace

```bash
kubectl create namespace development
```

Delete namespace

```bash
kubectl delete namespace development
```

List pods in a namespace

```bash
kubectl get pods -n development
```

List all pods

```bash
kubectl get pods --all-namespaces
```

List ConfigMaps in a namespace

```bash
kubectl get configmaps -n kube-system
```

List ConfigMaps in all namespaces

```bash
kubectl get configmaps --all-namespaces
```

---

# Key Points to Remember

- A Namespace provides logical isolation inside a Kubernetes cluster.
- Multiple teams can safely share the same cluster using namespaces.
- Every namespace has its own Pods, ConfigMaps, Secrets, Services, and Deployments.
- Kubernetes automatically creates several default namespaces.
- Resources with the same name can exist in different namespaces.
- Use the `-n` option to work with a specific namespace.
- Use `--all-namespaces` to view resources across the entire cluster.
- Common namespaces include **DEV**, **UAT**, **TEST**, and **PROD** for environment separation.
