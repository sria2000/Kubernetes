# Kubernetes NodePort Service

## What is a NodePort Service?

A **NodePort** Service exposes an application running inside a Kubernetes cluster to external clients.

When you create a Service of type **NodePort**, Kubernetes:

- Creates a **ClusterIP** internally.
- Opens a port on **every node** in the cluster.
- Forwards traffic received on that port to the backend Pods.

The default NodePort range is:

```
30000 - 32767
```

Any request sent to:

```
<Node-IP>:<NodePort>
```

is automatically forwarded to the Service, which then load balances traffic to one of the backend Pods.

---

# How NodePort Works

```
                 Internet / External Client
                           |
                           |
                  Node IP : NodePort
                 (172.30.2.2:30424)
                           |
                           |
                  NodePort Service
                           |
                           |
                     ClusterIP Service
                           |
                ------------------------
                |                      |
          Backend Pod 1          Backend Pod 2
```

The client never communicates directly with the Pods.

---

# Key Features

- Exposes applications outside the Kubernetes cluster.
- Opens the same port on **every node**.
- Automatically creates a **ClusterIP** Service.
- Performs load balancing across matching Pods.
- Default NodePort range is **30000–32767**.
- Commonly used for development, testing, and small environments.

# Create a NodePort Service

Base Service Manifest:

```yaml
apiVersion: v1
kind: Service

metadata:
  name: nodeport-service

spec:
  selector:
    app: backend

  ports:
    - port: 80
      targetPort: 80
```

Modify the manifest to use **NodePort**.

```yaml
apiVersion: v1
kind: Service

metadata:
  name: nodeport-service

spec:
  type: NodePort

  selector:
    app: backend

  ports:
    - port: 80
      targetPort: 80
```

Create the Service.

```bash
kubectl create -f service.yaml
```

Verify.

```bash
kubectl get service
```

Example:

```
NAME               TYPE       CLUSTER-IP       EXTERNAL-IP   PORT(S)

nodeport-service   NodePort   10.103.240.205   <none>        80:30424/TCP
```

Notice:

- Service Type = **NodePort**
- ClusterIP is still assigned.
- Kubernetes automatically allocated NodePort **30424**.

# Create Backend Pods

Create one or more backend Pods.

```bash
kubectl run backend-pod --image=nginx
```

Apply the required label.

```bash
kubectl label pod backend-pod app=backend
```

If multiple Pods have the same label, Kubernetes automatically registers them as Service Endpoints.

Example:

```
Endpoints:

192.168.1.253:80

192.168.1.129:80
```

The Service now load balances traffic between both Pods.

# Find the Node IP

Display the node addresses.

```bash
kubectl get nodes -o wide
```

Example:

```
NAME           INTERNAL-IP

controlplane   172.30.1.2

node01         172.30.2.2
```

Notice:

```
EXTERNAL-IP

<none>
```

This is expected for local, lab, Kind, Minikube, Kubeadm, or KodeKloud clusters.

NodePort works using the **Node IP**, not necessarily a public IP.

# Access the Application

Use the Node IP together with the allocated NodePort.

```bash
curl 172.30.2.2:30424
```

Expected output:

```
Welcome to nginx!
```

Traffic Flow:

```
curl 172.30.2.2:30424

          |
          v

NodePort Service

          |

ClusterIP Service

          |

Backend Pods
```

# Why Doesn't NodePort Show an External IP?

Many beginners expect this:

```
EXTERNAL-IP

35.120.10.25
```

Instead they see:

```
EXTERNAL-IP

<none>
```

This is completely normal.

NodePort **does not create a public IP address**.

Instead, Kubernetes simply opens a port on every node.

You access the application using:

```
<Node-IP>:<NodePort>
```

For example:

```
172.30.2.2:30424
```

Only a **LoadBalancer** Service automatically receives a public IP from a cloud provider.

# Create a NodePort Service Using CLI

Display help.

```bash
kubectl create service nodeport --help
```

Generate YAML without creating the Service.

```bash
kubectl create service nodeport test-nodeport \
    --tcp=80:80 \
    --dry-run=client \
    -o yaml
```

Example output:

```yaml
apiVersion: v1
kind: Service

metadata:
  labels:
    app: test-nodeport
  name: test-nodeport

spec:
  ports:
    - port: 80
      protocol: TCP
      targetPort: 80

  selector:
    app: test-nodeport

  type: NodePort
```

# Manually Specify the NodePort

Instead of allowing Kubernetes to choose a random NodePort, you can define one explicitly.

```yaml
apiVersion: v1
kind: Service

metadata:
  name: nodeport-service

spec:
  type: NodePort

  selector:
    app: backend

  ports:
    - port: 80
      targetPort: 80
      nodePort: 30556
```

Delete the existing Service.

```bash
kubectl delete service nodeport-service
```

Create the updated Service.

```bash
kubectl apply -f service.yaml
```

Verify.

```bash
kubectl describe service nodeport-service
```

You should see:

```
NodePort:
30556/TCP
```

Now the application is always accessible using:

```
<Node-IP>:30556
```

---

# Port vs TargetPort vs NodePort

| Field | Description |
|--------|-------------|
| **Port** | Port exposed by the Service inside the cluster |
| **TargetPort** | Port on which the application listens inside the Pod |
| **NodePort** | Port opened on every Kubernetes node for external access |

Example:

```
Client
     |
     | 30556
     |
NodePort
     |
     | 80
     |
Service
     |
     | 80
     |
NGINX Pod
```

---

# ClusterIP vs NodePort

| ClusterIP | NodePort |
|------------|----------|
| Internal communication only | Allows external access |
| Accessible only inside the cluster | Accessible using `<Node-IP>:<NodePort>` |
| Default Service type | Must be explicitly specified |
| No node port opened | Opens a port on every node |
| Used for microservices | Used for development and testing |

# Interview Questions

### What is a NodePort Service?

A NodePort Service exposes an application outside the Kubernetes cluster by opening a port on every node and forwarding traffic to backend Pods.

---

### What is the default NodePort range?

```
30000–32767
```

---

### Does a NodePort Service also create a ClusterIP?

Yes.

Every NodePort Service automatically creates a ClusterIP Service internally.

---

### Why is the EXTERNAL-IP shown as `<none>`?

NodePort does not provision a public IP address. It uses the existing node IPs. Public IPs are typically provided only by a **LoadBalancer** Service in cloud environments.

---

### How do you access a NodePort Service?

Using:

```
<Node-IP>:<NodePort>
```

Example:

```
172.30.2.2:30424
```

---

# Key Takeaways

- **NodePort** exposes an application outside the Kubernetes cluster.
- Kubernetes opens the same port on every node.
- The default NodePort range is **30000–32767**.
- Every NodePort Service automatically creates a **ClusterIP** Service.
- Traffic sent to `<Node-IP>:<NodePort>` is forwarded to the backend Pods.
- NodePort is commonly used for development, testing, and small environments.
- In local or self-managed clusters, `EXTERNAL-IP` is usually `<none>`, which is expected behavior.
- For production environments requiring a public IP, use a **LoadBalancer** Service.
