# Kubernetes PriorityClass

## What is PriorityClass?

By default, all Pods are treated equally by the Kubernetes scheduler.

**PriorityClass** allows you to assign a priority value to Pods so that Kubernetes knows which Pods are more important.

When the cluster runs out of resources:

- Higher priority Pods are scheduled first.
- Lower priority Pods may be **preempted (evicted)** to make room for higher priority Pods.

---

# Why do we need PriorityClass?

Imagine a Kubernetes cluster running:

- Banking Application
- Monitoring Agent
- Logging Service
- Test Application

If there is not enough CPU or Memory:

- The Banking application should continue running.
- The Test application can be stopped.

PriorityClass allows Kubernetes to make this decision automatically.

---

# Advantages of PriorityClass

PriorityClass influences two important things.

| Feature | Description |
|----------|-------------|
| Scheduling Order | Higher priority Pods are scheduled before lower priority Pods. |
| Preemption | If resources are unavailable, Kubernetes can evict lower-priority Pods to schedule higher-priority Pods. |

---

# Important Points

- Every Pod can have a priority.
- Priority indicates the importance of a Pod.
- Scheduler always tries to schedule higher-priority Pods first.
- If required, Kubernetes can preempt (evict) lower-priority Pods.
- PriorityClass values are integers.
- Maximum allowed value is **1,000,000,000 (1 billion)**.

# PriorityClass Object

Create a PriorityClass.

```yaml
apiVersion: scheduling.k8s.io/v1
kind: PriorityClass
metadata:
  name: high-priority
value: 1000
globalDefault: false
description: "This priority class should be used for XYZ service pods only."
```

Apply

```bash
kubectl apply -f priority.yaml
```

---

# Using PriorityClass in a Pod

```yaml
apiVersion: v1
kind: Pod
metadata:
  name: nginx
  labels:
    env: test

spec:
  priorityClassName: high-priority

  containers:
  - name: nginx
    image: nginx
    imagePullPolicy: IfNotPresent
```

Apply

```bash
kubectl apply -f pod.yaml
```

# Create Priority Classes using kubectl

Create High Priority

```bash
kubectl create priorityclass high-priority \
--value=1000 \
--description="high priority"
```

Create Low Priority

```bash
kubectl create priorityclass low-priority \
--value=100 \
--description="low priority"
```

Verify

```bash
kubectl get priorityclass
```

---

# Example 1 - Low Priority Deployment

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: low-priority-deploy

spec:
  replicas: 3

  selector:
    matchLabels:
      app: low-priority

  template:
    metadata:
      labels:
        app: low-priority

    spec:
      priorityClassName: low-priority

      containers:
      - name: busybox
        image: nginx

        resources:
          requests:
            memory: "50Mi"
            cpu: "30m"
```

Create

```bash
kubectl apply -f low-priority.yaml
```

Verify

```bash
kubectl get pods
```

---

# Example 2 - Deployment without Priority

If a Pod doesn't specify **priorityClassName**, Kubernetes assigns it the default priority (0).

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: no-priority-deploy

spec:
  replicas: 3

  selector:
    matchLabels:
      app: no-priority

  template:
    metadata:
      labels:
        app: no-priority

    spec:
      containers:
      - name: busybox
        image: nginx

        resources:
          requests:
            memory: "50Mi"
            cpu: "30m"
```

Create

```bash
kubectl apply -f no-priority.yaml
```

Verify

```bash
kubectl get deployments

kubectl get pods
```

Delete

```bash
kubectl delete -f no-priority.yaml
```

# How Scheduling Works

Suppose a node has resources for only **3 Pods**.

```
Node Capacity
─────────────
Pod-1
Pod-2
Pod-3
```

A new High Priority Pod arrives.

Without enough resources:

```
Scheduler
      │
      ▼
High Priority Pod
      │
      ▼
Evict Low Priority Pod
      │
      ▼
Schedule High Priority Pod
```

This process is called **Preemption**.

# Summary

- PriorityClass assigns importance to Pods.
- Higher priority Pods are scheduled first.
- Lower priority Pods can be preempted when resources are scarce.
- Pods without a PriorityClass get the default priority (0).
- Useful for production workloads, monitoring agents, logging agents, and critical infrastructure services.
- PriorityClass only influences scheduling; it does **not** reserve CPU or Memory. Resource Requests and Limits are still required for resource allocation.
