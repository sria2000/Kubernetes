# Kubernetes Container Probes

A **probe** is a health check performed by the **kubelet** on containers running inside a Pod.

The kubelet uses probes to determine:

- Whether the application has started successfully
- Whether the application is alive
- Whether the application is ready to receive traffic

Kubernetes provides three types of probes:

1. **Startup Probe**
2. **Liveness Probe**
3. **Readiness Probe**

---

# Types of Probes

## 1. Startup Probe

A startup probe determines whether an application inside a container has started successfully.

It is useful for applications that:

- Take a long time to initialise
- Require loading configuration
- Need database connections before becoming available

Example:

```yaml
startupProbe:
  httpGet:
    path: /health
    port: 8080
  failureThreshold: 30
  periodSeconds: 10
```

The kubelet waits for the startup probe to succeed before executing:

- Liveness probes
- Readiness probes

---

# 2. Liveness Probe

## Purpose

A **liveness probe determines whether a container is alive or not.**

If the liveness probe fails, Kubernetes assumes that the application is unhealthy.

Kubernetes will:

1. Kill the container
2. Restart the container

---

## Why do we need Liveness Probes?

A container can be in a running state but the application inside may not be working.

Example:

```
Container
    |
    |
    +---- Application Process
              |
              |
              +---- Deadlock
              |
              +---- Not responding
```

The process is running, but it cannot make progress.

A liveness probe detects this situation and restarts the container.

---

# Types of Liveness Probes

Kubernetes supports three types:

1. HTTP Probe
2. TCP Probe
3. Exec Probe

---

# 1. HTTP Liveness Probe

The kubelet sends an HTTP request to the container.

If the application returns:

```
HTTP 200 OK
```

The probe succeeds.

If the application returns:

```
HTTP 404
HTTP 500
Connection refused
```

The probe fails.

---

# Example: Nginx HTTP Liveness Probe

## live.yaml

```yaml
apiVersion: v1
kind: Pod

metadata:
  name: liveness-exec

spec:
  containers:

  - name: liveness
    image: nginx

    ports:
    - containerPort: 80

    livenessProbe:

      httpGet:
        path: /index.html
        port: 80

      initialDelaySeconds: 60
      periodSeconds: 5
```

---

## Deploy Pod

```bash
kubectl apply -f live.yaml
```

Check:

```bash
kubectl get pods
```

Output:

```
NAME             READY   STATUS
liveness-exec    1/1     Running
```

---

## Verify Liveness Probe

```bash
kubectl describe pod liveness-exec | grep -i live
```

Output:

```
Liveness:
http-get http://:80/index.html delay=60s timeout=1s period=5s
```

Meaning:

```
Container starts
       |
       |
Wait 60 seconds
       |
       |
Send HTTP request:
http://container-ip:80/index.html

Every 5 seconds repeat check
```

---

# Testing HTTP Liveness Failure

Enter the container:

```bash
kubectl exec -it liveness-exec -- bash
```

Remove nginx default page:

```bash
rm /usr/share/nginx/html/index.html
```

Now Kubernetes checks:

```
GET /index.html
```

Nginx returns:

```
HTTP 404
```

because the file no longer exists.

---

Check events:

```bash
kubectl describe pod liveness-exec
```

Output:

```
Warning  Unhealthy

Liveness probe failed:
HTTP probe failed with statuscode: 404
```

Kubernetes restarts the container:

```
Normal Killing

Container liveness failed liveness probe,
will be restarted
```

Verify:

```bash
kubectl get pod
```

Example:

```
NAME             READY   STATUS    RESTARTS
liveness-exec    1/1     Running   1
```

The restart count increased because the liveness probe failed.

# 2. Exec Liveness Probe

An exec probe runs a command inside the container.

The command exit code determines health.

Rules:

```
Exit Code 0
     |
     |
 Probe Successful


Exit Code != 0
     |
     |
 Probe Failed
```

---

# Example Exec Probe

```yaml
apiVersion: v1

kind: Pod

metadata:
  name: liveness

spec:

  containers:

  - name: liveness
    image: ubuntu
    tty: true

    livenessProbe:

      exec:
        command:
        - service
        - nginx
        - status

      initialDelaySeconds: 20
      periodSeconds: 5
```

---

The kubelet executes:

```bash
service nginx status
```

inside the container.

If:

```
Exit code = 0
```

Container is healthy.

If:

```
Exit code != 0
```

Container is unhealthy and Kubernetes restarts it.

---

# Testing Exec Probe

Enter container:

```bash
kubectl exec -it liveness -- bash
```

Run:

```bash
service nginx status
```

Check exit code:

```bash
echo $?
```

Successful:

```
0
```

Failed:

```
1
```

# Probe Configuration Parameters

## initialDelaySeconds

Defines how long Kubernetes waits before performing the first probe.

Example:

```yaml
initialDelaySeconds: 60
```

Flow:

```
Container starts

        |
        |
   Wait 60 seconds

        |
        |
First health check
```

---

## periodSeconds

Defines how frequently Kubernetes performs the probe.

Example:

```yaml
periodSeconds: 5
```

Meaning:

```
Every 5 seconds
perform health check
```

---

## failureThreshold

Number of consecutive failures before Kubernetes takes action.

Default:

```yaml
failureThreshold: 3
```

Example:

```
Probe fails
Probe fails
Probe fails

Restart container
```

---

## successThreshold

Number of successful checks required before considering the probe successful.

Default:

```yaml
successThreshold: 1
```

---

# Liveness vs Readiness vs Startup Probe

| Probe | Purpose | Failure Action |
|---|---|---|
| Startup Probe | Check application startup | Wait until application starts |
| Liveness Probe | Check application health | Restart container |
| Readiness Probe | Check if application can receive traffic | Remove Pod from Service endpoints |

---

# Real World Example

Consider a web application:

```
Pod
 |
 |
 +---- Application Container
          |
          |
          +---- Web Server
          |
          +---- Database Connection
```

---

## Liveness Probe

Question:

```
Is the application alive?
```

Failure action:

```
Restart container
```

---

## Readiness Probe

Question:

```
Can this application receive user traffic?
```

Failure action:

```
Remove Pod from Service endpoints
```

The container keeps running.

---

## Startup Probe

Question:

```
Has the application finished starting?
```

Failure action:

```
Continue waiting
```

---

# Interview Summary

- Liveness probe checks whether a container is alive.
- If liveness fails, kubelet restarts the container.
- It helps recover from deadlocks and hung applications.
- Kubernetes supports HTTP, TCP, and Exec probes.
- HTTP probe checks an application endpoint.
- Exec probe runs a command inside the container.
- Exit code `0` means success.
- Non-zero exit code means failure.
- Use startup probes for slow-starting applications.
- Use readiness probes to control traffic routing.
- Use liveness probes to automatically recover unhealthy containers.
