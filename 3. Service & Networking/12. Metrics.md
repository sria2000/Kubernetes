# Kubernetes Metrics Server

## Overview

**Metrics Server** is a lightweight cluster-wide aggregator of resource usage data.

It collects **CPU** and **Memory** usage from the **kubelet** running on each Kubernetes node and exposes the metrics through the **Kubernetes Metrics API**.

These metrics are used by:

- `kubectl top`
- Horizontal Pod Autoscaler (HPA)
- Kubernetes Dashboard
- Monitoring tools

> **Note:** Metrics Server is **not** intended for long-term monitoring. For historical metrics and dashboards, use tools such as **Prometheus** and **Grafana**.

---

# Metrics Server Architecture

```
+---------------------+
|      kubectl top    |
+----------+----------+
           |
           |
           v
+----------------------+
|    Metrics Server    |
+----------+-----------+
           |
           |
           v
+----------------------+
|      Kubelet         |
|  (on each Node)      |
+----------+-----------+
           |
           |
           v
+----------------------+
|   CPU & Memory       |
|   Usage Statistics   |
+----------------------+
```

# Verify Metrics Server

By default, Metrics Server is **not installed** on many Kubernetes clusters.

Run:

```bash
kubectl top pods
```

Example:

```text
root@controlplane:~$ kubectl top pods
error: Metrics API not available
```

This indicates that the Metrics Server is not installed or is not functioning correctly.

---

# Install Metrics Server

Install the latest Metrics Server components:

```bash
kubectl apply -f https://github.com/kubernetes-sigs/metrics-server/releases/latest/download/components.yaml
```

Example output:

```text
serviceaccount/metrics-server created
clusterrole.rbac.authorization.k8s.io/system:aggregated-metrics-reader created
clusterrole.rbac.authorization.k8s.io/system:metrics-server created
rolebinding.rbac.authorization.k8s.io/metrics-server-auth-reader created
clusterrolebinding.rbac.authorization.k8s.io/metrics-server:system:auth-delegator created
clusterrolebinding.rbac.authorization.k8s.io/system:metrics-server created
service/metrics-server created
deployment.apps/metrics-server created
apiservice.apiregistration.k8s.io/v1beta1.metrics.k8s.io created
```

# Troubleshooting

## Error

```text
error: Metrics API not available
```

Possible causes:

- Metrics Server is not installed.
- Metrics Server pod is not running.
- Metrics API is unavailable.
- Metrics Server cannot communicate with the kubelet.

---

## Lab Environment Issue

In lab environments such as **Kind**, **Kubeadm**, **Killercoda**, or **Play with Kubernetes**, the kubelet may use self-signed certificates.

The Metrics Server logs may show:

```text
tls: failed to verify certificate:
x509: cannot validate certificate because it doesn't contain any IP SANs
```

A common solution is to add the following arguments to the Metrics Server deployment:

```yaml
args:
- --kubelet-insecure-tls
- --kubelet-preferred-address-types=InternalIP,Hostname,ExternalIP
```

# Key Interview Points

- Metrics Server collects **CPU** and **Memory** usage from the **kubelet** on every node.
- It exposes metrics through the **Kubernetes Metrics API**.
- `kubectl top` depends on the Metrics Server.
- Horizontal Pod Autoscaler (HPA) also relies on the Metrics Server.
- Metrics Server provides **current resource usage** only; it does **not** store historical data.
- For long-term monitoring and alerting, use **Prometheus** and **Grafana**.
