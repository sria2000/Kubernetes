# Kubernetes Horizontal Pod Autoscaler (HPA)

## Overview

Application workloads are **not static**. They fluctuate based on:

- User demand
- Traffic spikes
- Seasonal workloads
- CPU-intensive processing
- Memory-intensive applications

The **Horizontal Pod Autoscaler (HPA)** automatically adjusts the **number of Pod replicas** in a Deployment, ReplicaSet or StatefulSet based on:

- CPU utilization
- Memory utilization
- Custom metrics
- External metrics

Unlike the **Vertical Pod Autoscaler (VPA)**, which changes CPU/Memory allocated to a Pod, **HPA scales by adding or removing Pods.**

# How HPA Works

```
                High CPU Usage
                      │
                      ▼
          +----------------------+
          |   Metrics Server     |
          +----------+-----------+
                     │
                     ▼
          +----------------------+
          |         HPA          |
          +----------+-----------+
                     │
      Increase / Decrease Replicas
                     │
                     ▼
          +----------------------+
          |     Deployment       |
          +----------+-----------+
                     │
          +----------+----------+
          |                     |
        Pod 1                Pod 2
                              Pod 3
                              Pod 4
```

---

# Prerequisites

HPA requires:

- Metrics Server installed
- CPU or Memory requests configured in the Pod
- A Deployment, ReplicaSet or StatefulSet

Verify Metrics Server:

```bash
kubectl top nodes
```

---

# Stabilization Window

The **Stabilization Window** prevents frequent scaling operations.

It tells HPA to wait for a period before scaling down to avoid unnecessary pod creation/removal.

| Action | Default |
|---------|---------|
| Scale Up | 0 seconds (Immediate) |
| Scale Down | 300 seconds (5 minutes) |

Example:

```yaml
behavior:
  scaleDown:
    stabilizationWindowSeconds: 60
```

The deployment waits **60 seconds** before removing Pods after CPU usage decreases.

# Method 1 - Create HPA Using YAML

## Step 1 - Create Deployment and Service

Create `deployment-svc.yaml`

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: php-apache

spec:
  selector:
    matchLabels:
      run: php-apache

  template:
    metadata:
      labels:
        run: php-apache

    spec:
      containers:
      - name: php-apache
        image: registry.k8s.io/hpa-example

        ports:
        - containerPort: 80

        resources:
          requests:
            cpu: 50m

---
apiVersion: v1
kind: Service

metadata:
  name: php-apache
  labels:
    run: php-apache

spec:
  selector:
    run: php-apache

  ports:
  - port: 80
```

Create the resources:

```bash
kubectl create -f deployment-svc.yaml
```

Verify:

```bash
kubectl get deployment
kubectl get pods
kubectl get svc
```

Example:

```text
NAME         READY   UP-TO-DATE   AVAILABLE
php-apache   1/1     1            1
```

---

## Step 2 - Create HPA

Create `hpa-stabilization.yaml`

```yaml
apiVersion: autoscaling/v2
kind: HorizontalPodAutoscaler

metadata:
  name: cpu-hpa

spec:

  scaleTargetRef:
    apiVersion: apps/v1
    kind: Deployment
    name: php-apache

  minReplicas: 1
  maxReplicas: 5

  metrics:

  - type: Resource

    resource:
      name: cpu

      target:
        type: Utilization
        averageUtilization: 50

  behavior:
    scaleDown:
      stabilizationWindowSeconds: 60
```

Apply:

```bash
kubectl apply -f hpa-stabilization.yaml
```

Verify:

```bash
kubectl get hpa
```

Example:

```text
NAME      REFERENCE               TARGETS     MINPODS   MAXPODS

cpu-hpa   Deployment/php-apache   cpu:2%/50%      1         5
```

---

## Step 3 - Watch HPA

Terminal 1

```bash
kubectl get hpa cpu-hpa --watch
```

Example:

```text
cpu-hpa   Deployment/php-apache   cpu:2%/50%       1      5      1

cpu-hpa   Deployment/php-apache   cpu:1508%/50%    1      5      1

cpu-hpa   Deployment/php-apache   cpu:1656%/50%    1      5      5

cpu-hpa   Deployment/php-apache   cpu:438%/50%     1      5      5

cpu-hpa   Deployment/php-apache   cpu:26%/50%      1      5      5

cpu-hpa   Deployment/php-apache   cpu:2%/50%       1      5      5
```

Notice that HPA increases replicas from **1 → 5** when CPU utilization exceeds the target.

## Step 4 - Generate Load

Open another terminal.

```bash

--rm \
--image=busybox:1.28 \
--restart=Never \

"while sleep 0.01; do wget -q -O- http://php-apache; done"
```

Watch Pods:

```bash
kubectl get pods
```

Example:

php-apache-8bfccb67-hb9kh

## Step 5 - Cleanup

```bash
kubectl delete -f deployment-svc.yaml

kubectl delete hpa cpu-hpa
```

# Method 2 - Create HPA Using kubectl

## Step 1 - Create Deployment

Create the Deployment and Service:

```bash
kubectl create -f deployment.yaml
```

---

## Step 2 - Create HPA

```bash
kubectl autoscale deployment php-apache \
--cpu-percent=50 \
--min=1 \
--max=3
```

> **Note:** In recent Kubernetes versions, `--cpu-percent` is deprecated. You may see the warning:

```text
Flag --cpu-percent has been deprecated.
Use --cpu with percentage or resource quantity format.
```

Verify:

```bash
kubectl get hpa
```

Example:

```text
NAME         REFERENCE               TARGETS

php-apache   Deployment/php-apache   cpu:2%/50%
```

# Interview Points

- HPA automatically scales Pods horizontally.
- HPA requires the Metrics Server.
- HPA works with Deployments, ReplicaSets and StatefulSets.
- CPU/Memory **requests** must be configured for HPA to calculate utilization.
- Scaling decisions are based on CPU, Memory, Custom Metrics or External Metrics.
- Default scale-up happens immediately.
- Default scale-down stabilization window is **300 seconds (5 minutes)**.
- HPA increases or decreases the number of Pod replicas; it does **not** change Pod CPU or Memory limits.
- Common production use cases include web applications, APIs, microservices and event-driven workloads.
